# 프로젝트 히스토리

대화 중 반복 설명하기 번거로운 배경·맥락·의사결정을 기록하는 문서.
새로운 중요한 맥락이 쌓이면 이 문서에 계속 추가한다.

## 마켓맵 빈 카테고리 필터링은 백엔드 책임으로 정리 (2026-08-16)

`/api/market-map` 응답에 종목이 하나도 없는 빈 카테고리(예: "메모리", `items: []`, `children: []`, `totalMarketValue: 0`)가 그대로 ㅁ내려와서, 트리맵 화면에 빈 슬리버로 렌더링되는 문제가 있었음.

프론트에서 방어적으로 필터링하는 방법도 검토했지만, `/api/market-map`은 화면 렌더링 전용 엔드포인트이고 카테고리 체계 자체는 별도 엔드포인트(`/admin/market-map/categories`)가 담당하므로, **빈 카테고리를 걸러서 내려주는 건 백엔드 책임**으로 정리함. 프론트 코드에는 필터링 로직을 넣지 않기로 함 (백엔드가 종목이 하나도 없는 카테고리는 응답에서 제외하도록 처리한다고 가정).

## 시가총액 구간 필터 — 마켓맵/어드민 종목관리 (2026-08-22)

마켓맵 페이지와 마켓맵 어드민 종목관리 페이지 양쪽에 시가총액 구간 필터를 추가하기로 함. 기준은 두 화면 동일:

- 소형주: 5천억 미만
- 중형주: 5천억 ~ 5조
- 대형주: 5조 ~ 200조
- 초대형주: 200조 이상

두 화면의 구현 방식은 다르게 가져가기로 함:

- **마켓맵**: 백엔드가 threshold 파라미터를 받아 필터링 + 결과적으로 종목이 하나도 안 남는 카테고리를 트리에서 제거해서 내려줘야 함. 프론트에서 처리하면 카테고리별 합계(`totalMarketValue`) 재계산뿐 아니라 위의 "빈 카테고리 필터링" 이슈와 동일한 문제(빈 카테고리 정리)를 다시 프론트가 떠안게 되므로, 기존에 정리한 "빈 카테고리 정리는 백엔드 책임" 원칙과 일관되게 백엔드가 처리.
- **종목관리**: 이미 종목 전체 목록을 한 번에 받아오는 평평한(flat) 리스트라 카테고리 합계 재계산이나 빈 카테고리 문제가 없음. 백엔드를 다시 호출할 필요 없이 프론트에서 이미 받은 목록을 그대로 필터링.

아직 구현 전, 기준/역할 분담만 확정된 상태. 백엔드 쪽에도 동일 내용 전달 필요.

## 마켓맵 등락률 범례 커스텀 기능 (설계만 확정, 미구현) (2026-08-27)

지금 등락률 색상은 코드에 하드고정돼있는데(`MarketMapBox.boxColorClass`가 4단계 계단식, `MarketMapCustomPage.CHANGE_RATE_LEGEND`가 별개로 하드코딩된 7칸/3단계 — 코드 주석에도 "박스 쪽은 4단계지만 범례는 3단계로 축약했다"고 명시돼 있어 실제 값 자체가 서로 어긋나 있음), 이걸 사용자가 직접 구성할 수 있게 만들기로 함. 아래는 하루 동안 여러 차례 이어서 다듬은 최종 설계.

**엔티티 설계(백엔드, 가칭)**: 항목마다 `side`(+/-), `thresholdPercent`, `color`(렌더링에 실제 쓰는 값 — hex/HSL 등 하나), `colorLabel`(처음 톤 고를 때 선택한 이름 그대로 저장, red/orange/blue 등 — 렌더링과 무관, 사람이 raw 데이터 볼 때 참고용). `displayOrder`는 불필요(`thresholdPercent` 자체가 정렬 기준). 색상은 hue+채도/명도를 별도 필드로 안 쪼개고 최종 결과값 하나만 저장(디테일 불필요, "레드면 다 레드"). 한국장 상한은 30%로 고정.

**색칠 방식 = 계단식이 아니라 그라데이션 보간**: 지금은 구간 안이면 무조건 같은 고정색(계단식)인데, 새 구조에서는 임계값들을 그라데이션의 "색상 정지점(stop)"으로 취급함. 종목의 실제 등락률이 두 stop 사이 어디인지 찾아 그 위치 비율만큼 두 stop 색을 보간(같은 톤이면 RGB, 톤이 다르면 HSL 기준이 더 안전)해서 그 종목 색으로 씀. 그래서 Tailwind 고정 클래스 대신 실제 계산된 hex를 `style={{backgroundColor}}`로 칠하는 방식으로 전환. **가장 큰 stop보다 등락률이 크면 그 이후는 자동 추정하지 않고 그 stop 색 그대로 clamp**(CSS 그라데이션/D3 스케일의 표준 동작과 동일) — 사용자가 준 적 없는 정보를 만들어내는 걸 피함.

**개념적으로는 사용자가 고르는 색은 3개뿐(0/+/-)**: +는 (0의 색)↔(+의 색) 사이를, -는 (0의 색)↔(-의 색) 사이를 등락률 비율로 섞는 게 기본. 다만 특정 stop 하나만 골라서 이 공식과 다른 색으로 덮어쓰는 것도 허용하기로 함 — 보간 로직은 "이 지점의 최종 색값이 뭐냐"만 보고 앞뒤 stop과 매끄럽게 이어붙이므로 별도 예외처리 없이 그대로 동작함. 다만 UI 관점에서 중간에 톤을 확 바꾸면(예: 초록 스케일 중간에 핑크) 히트맵의 "색만 보고 즉각 강도 파악"이라는 핵심 가독성이 깨질 위험이 있어, 기능은 열어두되 기본 흐름은 톤 유지를 유도하고 개별 override는 고급 설정처럼 덜 눈에 띄게 두는 정도로 절충하기로 함.

**커스텀 on/off는 두 단계**: (1) 마켓맵의 "커스텀 모드"(카테고리 트리 커스텀 여부, 기존 개념)와는 별개로 (2) "색상 커스텀" on/off 토글이 하나 더 필요함. 이 토글이 꺼져 있으면(또는 커스텀 모드 자체가 꺼져 있으면) 저장된 값과 무관하게 박스/범례 둘 다 고정 기본 프리셋(2/5/8, 기본 톤)을 그대로 씀 — 렌더링 쪽엔 분기가 없음. 켜져 있을 때 사이드(0/+/-)별로 독립적으로 판단: 그 사이드에 사용자가 저장한 stop이 하나라도 있으면 있는 그대로 사용(개수를 2/5/8 프리셋 형태에 맞춰 자동으로 채워 넣거나 할 필요 전혀 없음 — 보간 로직 자체가 stop이 몇 개든 그대로 처리하므로), 하나도 없으면 그 사이드만 조회 시점에 기본 프리셋 값으로 대체해서 렌더링(저장 데이터를 건드리는 게 아니라 순수 조회 시점 fallback).

**프론트 라이브 프리뷰**: 톤 선택 + 그라데이션 바 드래그 중(저장 전) 실제 종목 박스 색이 바로 반영되는 것도 가능 — 백엔드 왕복 없이 로컬 draft state만 바뀌면 렌더가 즉시 반영하는 구조. "저장" 눌러야 실제 백엔드 반영.

## 옵션 사이드바 재구성 + 지도 페이지 상단바/레이아웃 정리 (2026-09-14)

지마켓 산스(무료 배포) 폰트를 `public/fonts/`에 자체 호스팅으로 추가해 전역 기본 폰트로 적용(Pretendard는 폴백 유지, 300/500/700만 있어 400은 브라우저가 자동으로 500에 매핑).

**세 번째 바(제목/커스텀모드/시간) — 사이드바 열면 같이 밀리도록 원복**: 한때 사이드바가 열려도 세 번째 바는 침범하지 않고 본문만 밀리게 만들었었는데, 다시 세 번째 바까지 같이 밀리는 원래 구조로 되돌림. `captureRef`를 flex-row로 바꾸고 [세 번째 바+본문]을 하나의 flex-col 컬럼으로 묶은 뒤 `SettingsSidebar`를 그 컬럼과 형제(row)로 둠 — 지도/섹터/요약/커스텀(어드민) 4개 페이지 전부 동일 구조. 이때 섹터 페이지만 그래프 영역의 `whitespace-nowrap` 카테고리명 때문에 min-content 폭이 넓어서 창을 좁히면 사이드바가 밀려 보이는 문제가 있었는데, 컬럼에 `min-w-0`을 줘서 해결(4개 페이지 전부 방어적으로 적용).

**옵션 사이드바 계층 재구성**: "표시 범위" 하위에 있던 항목들을 "업종 분류"(업종 분류 레벨 + 등락률/등락종목수/시가총액합 지표), "종목"(종목 박스 표기, 종목 텍스트 표시 기준, 지도 전용 "등락률 자리수"), "표시 범위"(시가총액) 세 개의 중제목으로 나누고 각각 구분선(border-b)으로 분리. "제외 섹터" → "제외 범위", "색상 설정" → "색상 범위"로 명칭 변경, "색상 커스텀 모드" 토글은 별도 줄 없이 "색상 범위" 제목 우측에 스위치만 배치(`ToggleSwitch`에 `hideLabel` 옵션 추가). 토글들은 전부 "라벨 좌측 - 스위치 우측 끝" 레이아웃으로 통일.

**지도 페이지 전용 "등락률 자리수" 설정**: 등락률(%) 표시 소수점 자릿수를 정수/소수1자리/소수2자리 중에서 고를 수 있게 함(기본 소수2자리, 기존 동작과 동일). `toPctSigned`/`toPct`에 옵션 인자로 추가해서 안 넘기면 기존과 동일하게 동작 — 요약/섹터 등 다른 페이지는 영향 없음. `SettingsDisplayRangeSection`에 `showDecimalPlaces`(기본 false) prop을 둬서 지도 페이지에서만 노출(섹터는 그래프 자체 소수점 포맷을 따로 씀). 같은 패턴(opt-in prop)을 "동일 가중" 토글을 커스텀모드 스티키 블록 안으로 합칠 때도 씀(`showEqualWeightToggle`) — 섹터 페이지는 기존처럼 별도 `SettingsEqualWeightSection`을 그대로 쓰므로 중복 렌더 없음.

**"업종 분류 레벨" 슬라이더 "끄기" = 완전 평탄화**: 뎁스 0을 고르면 카테고리 구분 없이 지금 보이는 위치(전체 또는 드릴다운 중인 카테고리) 아래 모든 종목을 하나로 모아서 보여줌. 드릴다운으로 들어온 카테고리의 헤더를 breadcrumb과 중복 안 되게 숨기던 기존 `isSelf` 메커니즘을 그대로 재사용 — 합성 카테고리 하나(`categoryId: -1`, `categoryName: '__flat__'`)를 만들어 `selfCategoryName`으로 매칭시켜 대분류 헤더까지 포함해 카테고리 박스 자체가 안 보이게 함. 종목 박스는 원래 클릭 핸들러가 없어서 이 상태에서 클릭해도 자연히 아무 반응 없음(의도된 동작). d3 트리맵이 이미 `totalMarketValue` 내림차순 정렬이라 평탄화해도 시가총액 순서는 그대로 유지됨.

**섹터 페이지 그래프**: 하단 퍼센트 눈금 행 제거. "변화율" 그래프의 before 데이터가 없어도(장 시작 직후 등) 헤더(15/30/60분 라디오 등)는 계속 보이고 조작 가능하도록 수정 — 예전엔 `rankedItems`가 비면 헤더까지 통째로 안 그려서 아예 사라졌었음.

**렌더링 성능 검토(구현 전 마지막 점검, 결론: 문제없음, 단 주의점 있음)**: 종목 하나당 보간 연산(어느 두 stop 사이인지 찾기 + 비율 계산 + 색 섞기)은 stop 개수가 적어서(보통 한 자릿수) 무시할 수준. 실제 위험 포인트는 **그라데이션 드래그 라이브 프리뷰의 리렌더 빈도** — `MarketMapBox`/`MarketMapCategorySection`/`MarketMapTreemap` 전부 현재 `memo`/`useMemo`가 하나도 없어서, `mousemove`(초당 60~120회)를 그대로 state에 반영하면 맵 전체(박스 수백~수천 개)가 그 빈도로 통째로 리렌더될 수 있음. 대응: 드래그 좌표를 `requestAnimationFrame`으로 프레임당 한 번만 커밋(표준 쓰로틀링 기법). 그래도 버벅이면 그때 가서 박스 컴포넌트에 `memo` 경계를 추가해 영향받는 부호(+/-)만 리렌더되게 좁히는 걸 2차 대응으로 남겨둠 — 지금 미리 넣을 필요는 없음.

**오늘 확정된 추가 요구사항**: 지금처럼 박스 색칠 로직과 상단 범례바가 각자 따로 하드코딩되어 실제 값이 어긋나는 문제(임계값 개수/숫자 불일치)가 재발하지 않도록, 커스텀 off 상태(기본 프리셋)를 포함해서 **박스 색칠과 범례바 표시 둘 다 하나의 threshold+color 목록에서 파생**되게 만들 것.

**미구현 상태**: 백엔드 엔티티/API, 프론트 컬러피커·그라데이션 슬라이더 컴포넌트, 박스/범례 통합 렌더링 전환, rAF 쓰로틀링 전부 아직 시작 안 함.

### 프론트 구현 완료 (2026-08-27)

위 설계대로 프론트(박스/범례 렌더링 + 어드민 UI + MSW 목업)를 구현함. 백엔드 API(`GET /market-map/scale`, `PUT /admin/market-map/scale`)는 별도 에이전트가 병행 작업 중이라 계약만 보고 목업으로 개발/검증함.

- **핵심 모듈**: `src/utils/marketMapColorScale.ts` — `resolveMarketMapColor`(박스), `resolveLegendSwatches`(범례)가 항상 같은 함수/설정을 거치므로 구조적으로 어긋날 수 없음.
- **기본 프리셋(색상 커스텀 꺼짐/사이드에 stop 0개일 때 폴백) — 딱 3-stop만 사용**: 2%→red-950, 5%→red-900, 8%→red-500(마이너스는 blue 계열 동일). **8% 초과에 별도 stop을 더 두지 않음** — "가장 큰 stop 초과 시 clamp" 메커니즘이 8% 초과 전부를 자동으로 red-500/blue-500 고정값으로 유지해주므로, 오늘의 계단식 동작(8% 초과 flat)과 최대한 비슷하게 보임. (설계 중 한때 30%에 4번째 stop을 두는 안을 검토했으나, 그러면 8~30% 구간이 다시 서서히 옅어지는 그라데이션이 되어 "커스텀 끄면 오늘과 최대한 비슷해야 한다"는 목표에서 벗어나 폐기함. 30%는 어디까지나 종목 등락률의 물리적 상한일 뿐, stop을 반드시 그 지점에 둬야 한다는 뜻은 아니었음.)
- 색상값 출처: 추측이 아니라 `node_modules/tailwindcss/theme.css`의 실제 oklch 정의를 표준 OKLab→sRGB 변환식으로 직접 계산(zeroColor는 gray-600 `#4a5565`).
- **어드민 UI**: `src/components/MarketMapColorScaleAdmin.tsx` — `/admin/market-map?mode=colorScale`("색상 설정" 탭). 실제 `MarketMapTreemap`을 얹어 저장 전 draft config로 라이브 프리뷰. 라이트니스 슬라이더 드래그는 `useRafThrottledCallback`(신규 훅)으로 프레임당 1회만 커밋.
- 저장은 캐시 무효화(재조회) 대신 `queryClient.setQueryData`로 직접 반영 — 다른 admin 목업 핸들러들처럼 MSW가 실제로 값을 들고 있지 않아도 화면에 즉시 반영되게 하기 위함.

### 설정 팝업을 모달로 전환 + 색상 추가/수정을 사이드바 하단 패널로 분리 (2026-08-27)

드롭다운(`MarketMapColorScaleSettings.tsx`)이었던 톱니바퀴 설정 UI를 TradingView 참고 스타일의 모달(`MarketMapSettingsModal.tsx`)로 전면 교체하고, 색상 추가/수정만 별도 흐름으로 분리함.

- **모달 열림 상태를 페이지가 소유**: `isOpen`/`onOpenChange`를 `MarketMapCustomPage`가 들고 있음 — 색상 추가/수정 세션이 시작되면 모달을 잠깐 닫고(지도를 가리지 않기 위해), 세션이 끝나면(적용/취소) 다시 연다. 모달 자체는 언마운트되지 않으므로 좌측 네비 `activeSection`은 그대로 유지되지만, 본문 스크롤은 리마운트로 초기화되는 어긋남이 있어 `isOpen`이 true가 될 때마다 `requestAnimationFrame`으로 `activeSection` 위치로 다시 스크롤하는 처리를 추가함.
- **색상 추가/수정은 모달이 아니라 좌측 필터 사이드바 하단에 도킹된 패널**(`MarketMapColorStopEditorPanel.tsx`)에서 진행 — 모달은 지도를 `bg-black/70`으로 가리지만 사이드바는 가리지 않아서, 색을 조정하는 동안 실제 지도 색 변화를 라이브로 볼 수 있음. "적용"은 `useSaveMarketMapScale`로 즉시 저장 후 패널을 닫고 모달을 다시 열고, "취소"는 세션 시작 시점 스냅샷(`colorEditSnapshotRef`)으로 draft를 되돌림.
- **전역 "저장" 버튼 폐지** — 추가/수정은 각 세션의 "적용"이, 삭제는 `window.confirm` 후 즉시 저장이 각자 독립적으로 처리. "다 고치고 한 번에 저장" 개념 자체가 없음.

### 색상 추가 패널 — 세션당 다중 행 지원 + 부호 토글 + 임계값 충돌 시 update 취급 (2026-08-27)

`MarketMapColorStopEditorPanel.tsx`를 편집 세션이 항상 1개 stop만 다루던 구조에서, add 모드에 한해 여러 stop을 한 세션 안에서 동시에 구성할 수 있는 구조로 확장(edit 모드는 여전히 1개만).

- 페이지 쪽 상태를 `colorEditIndex: number | null` → `colorEditIndices: number[]`로 전환. "+"(행 추가) 버튼은 add 모드에서만 보이고, 누르면 값이 비어있는(입력칸 빈 값, 색 미지정) 새 행이 세션에 추가됨.
- 임계값 입력은 직접 부호를 타이핑하지 않고 크기(0 이상)만 입력 + 옆의 +/− 토글로 부호를 고름. **크기가 0이면 어느 부호를 골랐든 무조건 0으로 정규화**해서 커밋(0에 부호 의미 없음).
- **임계값 충돌은 막지 않고 "적용" 시점에 update로 정리** — 세션 편집 도중엔 같은 임계값이 여러 행에 있어도 그대로 두고, "적용" 직전에 `Map<thresholdPercent, ColorScaleStop>`로 훑어서 나중 값이 이기도록(overwrite) 정리한 뒤 저장. "수정도 결국 update"라는 논리와 동일하게 맞춤. (요청 임계값이 이미 저장돼 있으면 "추가"로는 아예 막고 "수정"으로만 가능하게 하는 validation은 백엔드 작업 시점에 다시 논의하기로 하고 이번 라운드엔 반영 안 함.)
- **패널 구조 재설계**: 톤 프리셋(hue 그리드)과 명도 그라데이션 바를 행마다 따로 두지 않고 패널 최하단에 하나만 공유 — 지금 커서가 들어가 있는(포커스된) 행에만 적용됨. 회색 프리셋을 추가해 8개(4x4 그리드, 정확히 2줄)로 맞췄고, 회색은 채도 0으로 별도 처리. 패널 전체 높이는 행 개수와 무관하게 고정(24rem)이고, 행 목록 영역만 정해진 높이(~4행) 안에서 자체 스크롤됨 — 톤 프리셋/그라데이션/적용·취소 버튼 위치는 항상 고정.
- 새 행의 미지정 상태 색값(`UNSET_COLOR_SCALE_STOP_COLOR`, 회색과 동일)은 `src/utils/marketMapColorScale.ts`에 둬서 페이지와 패널 컴포넌트가 공유(react-refresh 규칙상 컴포넌트 파일에서 상수를 export하면 안 돼서 유틸로 이동).

## 카테고리 등락률 랭킹/급변 기능 — 설계만 확정, 보류 (2026-08-28)

TradingView "1 DAY PERFORMANCE" 스타일로, 지정한 카테고리 레벨의 가중평균 등락률 랭킹을 바 차트로 보여주는 기능 논의. 상세 설계(스냅샷/재배정 이력, 캡션 텍스트 캐싱 등)는 market-monitor-backend의 `docs/history.md` 같은 날짜 섹션 참고 — 백엔드 위주 설계였음. 프론트 쪽만 요약:

- **"지금" 기준 랭킹은 새 API 불필요** — 이미 `useMarketMap(market, isCustom)`이 `MARKET_DATA_CACHE`(staleTime/refetchInterval 60초)로 캐싱해둔 트리 데이터를 그대로 재사용하면 됨. 같은 쿼리 키로 여러 컴포넌트가 붙어도 react-query가 자동으로 공유·중복요청 제거하므로, 새 탭/섹션은 그냥 같은 훅을 불러서 지정 레벨까지 순회 → 정렬 → 렌더만 하면 됨.
- **가중평균 등락률 계산을 백엔드로 이관하기로 함** — 지금은 `MarketMapCategorySection.tsx`가 `category.items`(원본 종목별 changeRate+시총)를 매 렌더마다 client-side로 가중평균 계산하는데, 백엔드가 캡션 텍스트(별도 세션 참고)를 만들려면 이 값을 서버에서도 계산해야 해서, `MarketMapCategoryNode` 응답에 필드로 실어 보내고 프론트는 그 값을 그대로 쓰는 쪽으로 방향을 잡음(이관되면 이 컴포넌트의 로컬 계산 로직 제거 대상). 상승/하락/보합 카운트는 이관 대상 아님 — 원본 종목 리스트는 박스 렌더링 때문에 어차피 계속 받아야 해서 그 자리에서 계산해도 무방하고, 백엔드 쪽 소비자도 없음.
- **"직전 대비 급변" 랭킹(스냅샷+카테고리 재배정 이력 기반)은 설계만 잡고 구현 보류** — 상세는 백엔드 history.md 참고.
- 현재 상태: 전부 설계 단계, 구현 착수 안 함.

### 후속 논의 — 응답 모양, before 시점 결정, 토글 UX (2026-08-28)

위 "직전 대비 급변" 랭킹을 다시 진행하기로 하면서 백엔드 세션에서 이어서 확정한 내용. 상세 계산/쿼리 설계는 백엔드 `docs/history.md` 참고, 여기는 프론트에서 알아야 할 부분만.

**API 응답 모양**: `beforeItems`/`nowItems`처럼 두 리스트로 병렬로 내려주는 대신, 카테고리 아이템 하나 안에 `now`/`before`를 같이 묶어서 내려주는 걸로 확정. `before`는 직전 스냅샷이 없으면 `null`.

```
List<CategoryChangeRateItem>
  - categoryId, categoryName
  - now: { snapshotTime, weightedAvgChangeRate, simpleAvgChangeRate }
  - before: { snapshotTime, weightedAvgChangeRate, simpleAvgChangeRate } | null
```

토글 두 개는 전부 프론트에서 이 하나의 리스트로 처리:
- **가중/산술평균 토글**: `now.weightedAvgChangeRate` vs `now.simpleAvgChangeRate` 중 뭘로 정렬할지만 바꿈.
- **현재/변화율 랭킹 토글**: 현재 랭킹은 `now.xxx` 기준 정렬, 변화율 랭킹은 프론트에서 `now.xxx - before.xxx` 계산해서 정렬.

**`before` 시점 = `latestSnapshotTime - beforeMinutes`(기본 60분, 화면에서 파라미터로 조절 가능하게 할 예정)**. 이 시점에 정확히 일치하는 스냅샷이 없으면(수집 주기 5분 기준 갭이 있거나, 장 시작 직후라 그 시각 자체가 아직 없거나) `before`는 그냥 없는 것으로 처리 — 가장 가까운 다른 시점 데이터로 조용히 대체하지 않음(예: 실제로는 63분 전 데이터인데 "60분 전"이라고 잘못 라벨링하는 걸 피하기 위해). 정상 상태를 가장한 부정확한 값보다, 없으면 없다고 명확히 보여주는 쪽을 택함.

**토글 UX 원칙 — 토글 상태와 실제 보여지는 데이터 종류가 어긋나면 안 됨**:
- 등락률(현재) 토글 상태에서 그 자체 데이터가 없으면: "없음" 표시, 빈 화면. (거의 발생 안 하는 케이스)
- 변화율(직전 대비) 토글 상태에서 `before`가 없으면: 조용히 등락률 데이터로 대체해서 보여주지 않음. 대신 알림 팝업(카테고리 변경 시 뜨는 것과 비슷한 톤) — `mm-dd HH:mm 데이터가 없습니다` (mm-dd HH:mm은 시도했던 `before` 시각) — 띄운 뒤, 팝업이 닫히면 토글 **상태 자체**를 등락률로 전환(그 화면에서 등락률 데이터를 그냥 보여주는 게 아니라, 토글의 선택값 자체를 바꿔서 "지금 등락률 랭킹을 보고 있다"는 상태와 실제 표시가 항상 일치하게 함).
- 이 케이스는 하루 중 최초 텔레그램 발송 시각(예: 08:10) 직후처럼 `before`가 원천적으로 존재할 수 없는 상황에서 확정적으로 발생함 — 이건 구조적 제약으로 받아들이고 감추지 않기로 함(사용자 의견: "오류에 대한 인지를 내가 해야 개선을 할 수 있지, 잘못된 걸 정상인 것마냥 보여주는 것보다는").

**미구현**: 위 전부 설계만 확정, 프론트/백엔드 모두 착수 전.

### 프론트 구현 완료 (2026-08-29)

백엔드가 `MarketMapCategoryNode`에 `weightedAvgChangeRate`/`simpleAvgChangeRate`를 실어 보내고 `/market-map/category-change-rates`를 추가한 뒤, 위 설계대로 프론트도 구현함.

## 섹터 "변화율" 그래프에 마켓 지수 바 (2026-09-13, PR #53)

섹터 페이지는 그래프를 둘 그린다("현재", "변화율"). 노란 마켓 지수 바가 **"현재"에만** 붙어 있었다.
"변화율"은 N분 전 대비 %p 차이인데 지수 쪽 과거값을 백엔드가 안 내려줬기 때문이다.

백엔드가 응답 필드를 값 하나에서 now/before 짝으로 바꿨다.

```
전   indexChangeRate: 0.48
후   index: { now: 0.48, before: 0.15 }
```

### 배포 순서 — 프론트가 두 모양을 다 받는 릴리즈를 먼저 냈다

**zod의 `.nullable()`은 값이 `null`인 것을 허용할 뿐 키가 없는 것(`undefined`)은 허용하지 않는다.**
그건 `.optional()`이다. 이 작업은 필드를 더하는 것이 아니라 **바꾸는** 것이라, 그대로 두면 어느 쪽을
먼저 배포해도 `parse`가 실패해 섹터 페이지가 "데이터를 불러오지 못했습니다"가 된다. 그리고 그 화면이
15분마다 캡처돼 나간다.

그래서 프론트가 `index`와 `indexChangeRate`를 **둘 다 `.nullable().optional()`로** 받는 릴리즈를 먼저
내고, 그다음 백엔드를 배포했다. 폴백이 걸리는 구간에는 `before`가 없어 "변화율" 지수 바가 안 뜨는,
즉 그 전과 같은 화면이 된다.

**"zod가 모르는 키를 버린다"는 사실만 보고 백엔드 먼저라고 판단하면 틀린다.** 필드를 더하기만 하는
변경(위 `beforeMinutes` 건)과 필드를 바꾸는 변경은 순서가 반대다.

### 폴백을 걷어냈다 (PR #56)

백엔드가 배포돼 `indexChangeRate`가 더 이상 안 내려오므로 죽은 경로가 됐다. `src/types/api.ts`에서
그 필드를 지우고, `CategoryChangeRatePage.tsx`의 `indexBar` 폴백 가지를 지웠다.

**`index`에서 `.optional()`도 같이 뺐다.** 백엔드는 그 시각 지수 스냅샷이 없으면 `index: null`을
내려주고 키 자체를 빼지 않는다(Jackson 기본 inclusion이 `ALWAYS`이고 백엔드에 `@JsonInclude`도
`spring.jackson.default-property-inclusion`도 없다). `.optional()`을 남겨두면 백엔드가 필드를 통째로
빠뜨리는 회귀가 생겨도 화면이 조용히 지수 바 없이 그려진다. `.nullable()`만 남는 것이 원래 의미다.

헤더 색은 절대 depth, 크기는 상대 depth로 유지한다(2026-09-19).

업종 톱픽은 전체 지도 기준 절대 depth 순위로 강조하고 등락률은 가중 토글을 따른다(2026-09-19).

섹터 페이지는 /api/map 두 번(now, now−N분)으로 그린다. 카테고리 평균은 utils/categoryAverage 하나(하위 전체·구간만 거름)

## 지도 설정 아이콘 탭 재구성 (2026-09-27, PR #73)

지도와 섹터 설정은 config.png를 참조해 즐겨찾기, 종목 구성, 업종 분류, 종목 표시, 색상 아이콘 탭으로 나눴다. 기존 설정값을 그대로 사용하며 한 번에 한 탭만 표시한다. 즐겨찾기 탭은 선택할 수 있지만, 추가·현재 설정 저장·선택한 설정으로 불러오기 버튼은 기능 구현 전이라 비활성 상태다.

기존 커스텀 모드 값은 업종 분류의 거래소 분류(false)/MARKETRY 분류(true) 선택으로 옮겼다. 거래소 분류는 한 단계 대분류와 대분류 지표만 적용하고, MARKETRY에서 선택한 분류 단계 및 지표 범위는 보존해 전환 시 복원한다. 시가총액 구간, 종목 박스 표시, 색상 설정은 양쪽 분류에서 사용한다. 기존 동일 가중 값은 종목 표시의 시가총액 비례/동일 크기 선택으로 옮겼다. 이 값은 기존대로 박스 면적과 평균 등락률 방식에 함께 적용된다.

범례 편집 입력/적용/취소에서 NES 버튼 스타일을 제거했다. 상단 홈 아이콘은 첫 지도 경로로 이동하며, PR #71의 흰색 45% hover와 PR #72의 로컬 자동 로그인을 main 병합으로 함께 반영했다.

## 지도 설정 북마크·핀·항목 높이 통일 (2026-10-02)

**북마크**: 지도 설정 항목 12개(1-1~1-4, 2-1~2-3, 3-1~3-4, 4-1)에 북마크 버튼을 달고, 북마크한 항목을 원래 순서 그대로 "북마크" 탭(기존 즐겨찾기 탭)에 다시 그린다. 같은 컴포넌트를 두 곳에서 쓰고, 북마크 컨텍스트(`SettingsBookmarkContext`)의 `mode`로 원래 탭/북마크 탭을 구분한다. 북마크 탭의 번호는 원래 위치 번호("1-2)")로 보이고 CSS 카운터가 아니라 JS에서 계산한다. 로그인 사용자만 쓸 수 있다 — 서버 설정(`/api/custom/preferences`)의 `marketMap.settingsBookmarks`에 id 배열로 저장하고(백엔드 변경 없음), 비로그인이 누르면 저장 없이 로그인 팝업을 띄운다. 최대 5개이고 6개째 추가하면 알림만 띄운다. 지도 페이지에만 있다.

**항목 높이 통일**: 내용 높이를 재서 간격을 맞추면 글꼴/내용에 따라 0.5px 안팎으로 어긋나서, 항목마다 높이를 고정했다(127px = 가장 높은 항목 103px + 여백 24px, 첫 항목은 위 여백 20px 포함 147px). 제목이 탭 내용 위에서 20/147/274/401/528px에서 시작하고, 구분선은 두 번째 항목부터 제목 위 12px에 긋는다. 마지막 항목(1-4, 2-4, 3-5, 4-2)은 높이를 고정하지 않는다. 각 항목의 첫 컨트롤은 제목 아래 60px에서 시작한다(1-4의 슬라이더, 2-2의 선택 버튼 등 일부 예외). 항목 내용이 103px를 넘으면 `index.css`의 값을 다시 정해야 한다. 북마크 탭도 같은 규칙(`.settings-bookmark-item`)을 쓴다.

**업종 단계 드롭박스**: 2-2와 1-4의 대/중/소분류 글자 줄을 드롭박스(`DepthSelect`)로 바꿨다. 업종 표시 단계(1-1)보다 깊은 단계는 비활성이고, 누르면 안내 말풍선이 드롭박스 위쪽에 뜬다(아래에 두면 목록과 선택 버튼을 가린다). 단일값 슬라이더는 `input`을 `block`으로 바꿨다 — 인라인이면 줄 높이 때문에 눈금 글자가 범위 슬라이더보다 5px 아래로 밀렸다.

**핀(고정)**: 설정창 헤더의 ✕를 핀으로 바꿨다. 켜면(기본) 설정창을 지도 옆에 고정하고(지도를 밀어냄) 다음에도 열린 채로 시작한다. 끄면 지도 위에 띄우고(`absolute`, 지도를 밀지 않음) 설정창 밖을 누르면 닫히며 다음에도 닫힌 채로 시작한다. 위쪽 설정 버튼(`data-settings-toggle`)은 바깥 클릭에서 제외한다(토글이라 포함하면 닫혔다 다시 열린다). 로그인 사용자의 핀은 이 브라우저에만 저장하고(`useLocalPersistedState`), 비로그인은 항상 열림+핀 켜짐으로 시작한다. 로그인 사용자는 세션 확인 전에 잠깐 열렸다가 닫힐 수 있다.

**색상 탭**: 4-1 강조 색상에 흰색에 가까운 회색(`#e5e7eb`)을 맨 왼쪽에 추가해 4-2-2 색상 줄과 같은 8칸·같은 간격으로 맞췄다. 색상 범위 커스텀을 꺼도 편집 영역을 지우지 않고 흐리게 둔다(끌 때 편집을 취소하던 `handleChangeColorCustomOn`의 취소를 뺐다). 편집 영역을 항상 열어두는 `useEffect`(useGlobalSettings)가 커스텀 페이지에서 편집 패널을 항상 띄우던 문제는 `CustomManagePage`의 패널 코드를 지워서 해결했다.

**이동 경로 줄(지도 진입 시)**: 글자를 14px→18px로 키웠다(줄 높이 28px 그대로라 지도 영역 불변). 줄 전체를 눌러 전체로 가던 동작을 없애고, 이름과 오른쪽 되돌아가기 아이콘(↰)을 한 버튼으로 묶어 그 단계로만 이동한다. 지금 보고 있는 마지막 이름만 청록색이고 눌러도 아무 일이 없다.

**로컬 개발 참고**: `start-frontend.command`가 `VITE_LOCAL_AUTO_LOGIN=1`을 켜서, 로그아웃해도 새로고침하면 개발용 자동 로그인으로 다시 로그인된다(운영에는 영향 없음).

## 비로그인 기본값·로그아웃 초기화·설정 버전 관리 (2026-10-02, 이어서)

**기본값을 한 파일에**: 지도 설정 기본값을 `utils/settingDefaults.ts`에 모았다. 회원 기본값(`MEMBER_DEFAULTS`)이 기준이고 비로그인 기본값(`GUEST_DEFAULTS`)은 다른 항목만 `GUEST_OVERRIDES`에 적는다(1-1 대분류, 1-2 시총 가중, 1-3 대분류만, 1-4 대분류, 2-1 초대형주+대형주(`topTwoTiers`), 3-1 100%, 3-3 0.01%, 3-4 2자리). 3-5 팝업은 우클릭 그대로다. 처음 가입한 사용자에게는 별도 기본값(MARKETRY 버전)을 줄 예정이라 회원 기본값은 그때 따로 정한다. 사용자가 값을 바꿔 저장값이 생기면 그 값이 항상 우선한다. `usePageSetting`은 비로그인이 저장한 값이 없을 때 "지금 상태의" 기본값을 쓴다(처음 그려질 때 굳은 값을 쓰면 로그인 중에 만든 화면이 로그아웃 뒤에도 회원 기본값을 들고 있다). 비로그인이 바꾼 설정을 가입 후 계정으로 이어주는 건 하지 않기로 했다(별로 바꿀 것도 없고 가입 후 다시 만져보는 경험도 의미가 있다).

**로그아웃 시 이전 설정이 남던 문제**: `useLogout`이 `queryClient.clear()`로 세션 쿼리까지 지워서, 세션을 구독하던 지도 설정 화면이 새 쿼리를 따라가지 못해 이전 사용자 값이 그대로 보였다. 세션 쿼리는 지우지 않고 그 자리에서 익명으로 바꾼 뒤 나머지를 비운다. 비로그인이 처음 접속하면 등락률 색상은 기본 7칸(-8/-5/-2/0/+2/+5/+8)이어야 하는데, 편집 영역이 자동으로 -8%를 열면서 음수 쪽에 구간이 하나만 생겨 5칸이 됐다 — 저장된 구간이 하나도 없으면 기본 7칸을 실제 구간으로 채워서 시작한다(`createDefaultColorScale`).

**로그인 안내**: 로그인 팝업 제목은 "로그인", 문구는 "개인 설정은 로그인 후 이용할 수 있습니다."(청록색), 버튼은 "Google 로그인"(회색)과 "닫기"다. 비로그인이 북마크 탭이나 항목의 북마크 아이콘을 누르면 탭을 열지 않고 이 팝업을 띄운다.

**로컬 개발 `?guest=1`**: `start-frontend.command`가 자동 로그인(`VITE_LOCAL_AUTO_LOGIN=1`)을 켜서 로컬에서는 비로그인 화면을 보기 어렵다. 주소에 `?guest=1`을 붙여 열면 자동 로그인을 건너뛰고(남은 로그인 쿠키가 있으면 한 번 로그아웃) 탭을 닫을 때까지 비로그인이 유지되며 로그인 팝업도 열린다. `?guest=0`이면 자동 로그인으로 돌아간다. 로컬에는 구글 로그인 설정이 없어서 `Google 로그인` 버튼은 503이 난다.

**설정 저장값 버전 관리(`utils/settingsSchema.ts`)**: 서버 설정에 `settings.version`을 넣는다(현재 1). 설정을 불러올 때 버전이 낮거나 없으면 옮기는 규칙을 순서대로 적용하고 서버에 한 번 반영한다. **설정 키 이름을 바꾸거나 설정 항목을 없앨 때는 반드시 `SETTINGS_SCHEMA_VERSION`을 올리고 `MIGRATIONS`에 옮기는 규칙을 추가한다.** 북마크 id도 마찬가지이며, 저장된 북마크는 읽을 때 알려진 id만 남긴다(`sanitizeBookmarkIds`).

**호버 지연**: 종목 박스와 섹터 헤더의 흰색 하이라이트가 0.15초 서서히 켜져서 마우스를 빠르게 움직이면 늦게 따라왔다(켜지기까지 약 120ms). 올라갈 때는 즉시 켜고 벗어날 때만 0.1초로 사라지게 했다(약 7ms).

**4-1 강조 색상 말풍선**: 클릭 후 포커스가 남아 말풍선이 고정되고 다른 동그라미에 올리면 두 개가 떴다. 마우스를 올렸을 때만 뜨게 했다.

**시가총액 구간 이름**: 서버 기본 구간 "초대형주"(200조 이상)를 "Top 2"로 바꿨다(백엔드 `DEFAULT_TIERS`, 로그인 사용자의 구간은 이미 "Top 2"). 구간은 순위가 아니라 시가총액 기준이라, 세 번째 회사가 200조를 넘으면 이름과 어긋난다.

## 제외 업종(비로그인), 회원 기본값 통일, 색상 기본값 (2026-10-02, 이어서)

**비로그인 업종 제외**: 거래소 분류(KRX) 트리는 모든 업종의 `sectorId`가 0이라 id로 대상을 구별하는 제외 기능이 한 업종만 제외해도 전부 사라졌다. 비로그인에게는 업종 이름 경로로 만든 고유 음수 id를 붙이고(`utils/guestSectorIds.ts`), 우클릭 팝업의 제외 버튼과 2-4 제외 목록을 비로그인에게도 연다. 제외 목록은 서버에 저장하지 않고 이 탭에만 남으며 새로고침하면 초기화된다.

**회원 기본값 = 비로그인 기본값**: 가입 직후 사용자의 기본값은 비로그인과 같다(`MEMBER_DEFAULTS`를 비로그인 값으로 바꾸고 `GUEST_OVERRIDES`는 비움). 분류 체계만 다르다(비로그인 KRX, 회원 MARKETRY). 1-4 강세 표시는 대분류 1개다. 비로그인이 새로고침하면 지도·그룹 설정이 기본값으로 돌아간다(`utils/guestSettingsReset.ts`) — 설정 저장이 로그인의 장점이다.

**색상·설정 기본값(코드 하나로)**: 비로그인과 가입 직후 상태를 같게 하려고 기준을 프론트의 코드 기본값 하나로 둔다. 백엔드는 비로그인에게 빈 색상 스케일을 주고(`getDefaultScale`), 가입할 때 템플릿 계정의 저장 설정과 색상 구간을 복제하지 않는다(업종 분류, 종목 배정, 별칭, 시가총액 구간만 복제). 그래서 템플릿 계정에서 값을 바꿔도 신규 가입자에게 퍼지지 않고, 기본값을 바꾸려면 `settingDefaults.ts`와 `marketMapColorScale.ts`만 고친다. 코드 기본 색은 파랑(217)/빨강(0)을 같은 채도(75)와 같은 명도로 두고 명도는 색상 편집기 슬라이더의 10%/35%/60% 위치(2%=16, 5%=37, 8%=58)에 놓는다. 0%는 첫 색인 회색(채도 0)의 정가운데 명도(50)다(`#808080`). 이전에는 신규 가입자가 템플릿 계정의 저장 설정(강조 색상 등)까지 복사받았다.

**탭·말풍선**: 설정 탭 이름 "종목 표시"를 "종목 박스"로 바꿨다(안의 항목 "박스 내 표기"와 겹치지 않는다). 4-2-2 색 동그라미에도 4-1처럼 마우스를 올렸을 때 색 이름 말풍선이 뜬다.

**로그인 팝업 문구**: 오른쪽 위 로그인 버튼으로 연 팝업에서는 안내 문구를 숨긴다(`requireLogin(path, { hideMessage: true })`). 프로필 페이지는 비로그인이 들어오면 로고만 보이고 로그인 팝업이 뜬다(`NavBar`의 `hideAccount`). 커스텀 페이지는 그대로다.

**로그인 안내 문구**: 팝업·커스텀 페이지는 "로그인 후 이용 가능합니다."다. 프로필 페이지 직접 진입은 팝업을 바로 띄운다(로그인 후 돌아올 주소를 기억하므로 만료된 사용자에게 유리).

**설정 문구 정리 (2026-10-02)**: 제목 아래 설명 한 줄과 겹치는 물음표를 없앴다 — 3-5(제목을 "종목 정보"로), 히트맵 선택. 2-2 물음표 설명에서는 제목 아래 설명과 겹치는 첫 문장을 지웠다. 2-4 제목 "제외 업종 변경"을 "제외 업종"으로 바꿨다(다른 제목처럼 명사로). 대분류·중분류·소분류 같은 단계 이름은 세분류가 생기면 문구를 다시 고쳐야 해서 설명에 넣지 않는다.

## 커스텀 페이지 시트와 NXT (2026-10-02, 구상 중 1단계 완료)

**구상**: 커스텀 페이지에서 히트맵(내 히트맵/KRX/NXT/MARKETRY)별 분류·종목 탭을 엑셀 시트처럼 나눈다. 그러면 지도 설정의 저장값과 지도의 히트맵 선택이 커스텀 페이지와 독립으로 유지된다.

**정한 것**
- KRX 같은 거래소 분류 시트는 **읽기 전용**이다. 사용자별로 저장할 값이 거의 늘지 않고, 편집 가능한 것은 내 히트맵 하나뿐이라 "시트 A를 고쳤는데 지도는 B를 보여준다"는 혼란이 크지 않다. 내 히트맵 시트에 "지도에서 보기" 버튼 정도를 둔다.
- **NXT는 분류 시트가 아니라 데이터 모드**다. 업종 분류는 KRX가 하고, NXT는 NXT에서 거래되는 적은 수의 종목을 NXT 시세로 그리는 지도다(KRX 지도는 장 시작 전·마감 후에 거래가 없어 선명하지 않아서 따로 둔다). **NXT에는 거래가 없는 시간이 없고 종목 수만 적다.** 오히려 KRX가 거래되지 않는 시간이 있다. 따라서 NXT는 커스텀 페이지의 시트가 아니라 지도의 히트맵 선택(데이터 모드)에 둔다. 현재 NXT와 내 히트맵 버튼은 미구현(회색)이다.
- 종목 리스트를 따로 보고 싶은 사용자를 위해 **커스텀 종목 탭 표에 "NXT 거래 가능" 열과 "NXT만 보기" 필터**를 더하는 안이 별도 시트보다 가볍다.

**먼저 확인할 것**
- 서버에 NXT 정보가 **없다**(2026-10-02 로컬 확인: 종목 4,355개 중 NXT 코드(`_NX`)를 가진 것 0개, 종목 정보에 NXT 표시 열 없음). 키움이 NXT 거래 종목 목록을 직접 주는지(수집해서 저장 가능한지), 수기 입력이 필요한지부터 확인한다. 백엔드에는 키움 거래소 구분 코드(`ExchangeType`의 KRX/NXT/SOR, `StexType`의 KRX 단독/NXT 단독/합산)가 이미 있다.

설정창 하단의 NXT 단독 시간대 안내문은 삭제한다. 지도 본문의 닫을 수 있는 NXT 안내 팝업에서 같은 내용을 안내하므로 설정창에 중복 표시하지 않는다.

설정창 하단의 업데이트 시각은 선택한 분류를 따른다. MARKETRY는 운영자의 종목 분류 수정 시각, 한국거래소는 시스템에 저장된 활성 주권 종목 정보의 최종 동기화 시각이다. 거래소가 공식적으로 발표한 시각을 의미하지 않는다. 거래소 시각은 코스피·코스닥·NXT 필터와 무관하게 전체 분류에 동일하게 표시하며, 데이터가 없으면 MARKETRY 시각으로 대체하지 않는다. 커스텀 페이지도 선택한 분류에 맞춰 조회하며 새로고침 시 분류 시각을 다시 받는다. 도움말은 MARKETRY에서 `MARKETRY 운영자가 종목·업종 정보를 마지막으로 수정한 시각입니다.`로 표시한다. 한국거래소에서는 키움 REST API로 받은 종목·업종 정보를 서버에 마지막으로 동기화한 시각이며, 시세 갱신 시각이나 한국거래소의 공식 분류 변경 시각과는 다르다고 설명한다. 두 도움말은 ‘시각’으로 표현을 통일하며, 한국거래소 도움말은 문장 사이에 빈 줄을 두고 설정창 폭에 맞게 줄을 나눈다.

## 그룹 세로 막대와 그래프 선택 (2026-10-12)

그룹 그래프는 항목을 x축에 놓고 막대를 위로만 그린다. 음수도 절댓값만큼 위로 자라며, 부호는 기존 색상과 숫자로 구분한다. 항목명은 아래 한 줄에 45도 사선으로 배치한다. 양방향 안과 실제 데이터로 비교한 뒤 단방향을 선택했다.

## 종가·별도 모드의 종목 팝업 가격 이름 (2026-10-12)

종목 팝업의 가격 줄 이름은 등락률의 기준 가격에 맞춘다. 종가 모드는 `당일종가`와 `전일종가`, 누적 모드는 `현재가`와 `전일종가`, 별도 모드는 `현재가`와 `당일종가`를 보여 준다. 종가 모드의 값은 정규장 종가라서 현재가라고 부르면 틀리고, 별도 모드는 당일종가 대비로 계산하는데 팝업에 전일종가가 보여 등락률과 가격이 맞지 않았다. 이름표는 `useGlobalSettings`에서 모드에 따라 `rangeLabels`로 붙인다(기간 등락률이 쓰던 방식 그대로). 별도 모드의 당일종가 값은 백엔드가 전일종가 자리에 담아 보내므로(`AfterHoursChangeRates`) 프론트는 이름만 바꾼다.

헤더에는 종가 스냅샷의 실제 시각인 15:35가 그대로 보인다. 종가는 `[15:30, 15:40)` 구간의 마지막 스냅샷이고, 동시호가 체결이 늦게 반영되는 종목이 있어서 15:30 스냅샷만으로는 부족하다(백엔드 `docs/backlog.md`에 9월 15일 비교가 있다). 표시만 15:30으로 바꾸는 방법은 코드와 문서가 늘고 화면 시각과 데이터 시각이 어긋나 나중에 혼동을 부르므로 지금은 하지 않는다. 사용자가 15:35를 헷갈린다는 반응이 나오면 그때 다시 정한다. 백엔드 백로그의 「과거 날짜 조회」 절에 같은 고민이 미결로 있다.

수집 간격을 줄일 때 프론트에서 손볼 곳은 `GroupPage`의 `beforeMinutes % 5` 검사와 `NavBarPageActions`의 "5분 간격" 도움말이다. 종가 선택은 구간의 마지막 스냅샷이라 간격과 무관하다.

공식 종가를 증권사에서 받는 방법은 검토 중이다. 키움 `ka11081`은 공식 문서에서 주식일봉차트정규장조회요청으로 확인했고, `ka10086`(일별주가요청)에도 종가 필드가 있다. 두 TR 모두 장 마감 직후 당일 값이 나오는지와 정규장 값만 주는지는 문서에 없어서, 실제 호출로 15:35 스냅샷과 비교해 봐야 한다.

## 툴바 배지·칩과 메뉴 목록 (2026-10-13)

Map·Group·Custom 왼쪽 위의 시장·화면 드롭다운을 없앴다. 시장(KOSPI·KOSDAQ·ALL STOCK)과 화면(SECTOR·STOCK)은 상단 영역 메뉴(Map·Group·Custom)에 커서를 올리면 뜨는 목록에서 고르고, 터치 화면은 호버가 없어 메뉴를 눌러도 기본 화면으로만 간다. 툴바 맨 왼쪽에는 지금 보는 값을 제목 배지로 보여 준다. 폭은 가장 긴 ALL STOCK에 맞춘 7.5rem으로 고정해서 어느 페이지든 같다. 시도한 시안 중 분류 배지와 같은 색 조합(진한 청록 바탕·청록 하이라이트)은 어두운 푸른 회색 바탕이 더 어울려서 쓰지 않았다.

날짜·시각·시장 시간대·제외 종목은 각각 회색(#3b3b3b) 직사각형 칩이다. 높이는 제목 배지·분류 배지·Custom 검색창과 같은 24px이고, 모서리는 모두 직각이다. 눌리는 곳은 칩 전체가 버튼이고, 커서를 올리면 글자 색이 아니라 배지 면이 설정창 선택 줄 색(#838385)으로 바뀐다. 하루·기간을 골라 과거 값을 보는 동안에는 칩 글자가 청록이다. 시각 칩은 시계·시각 구역(눌러도 동작 없음)과 새로고침 아이콘 칸(배경 없이 청록 아이콘, 누르면 새로고침)으로 나눈다. 아이콘은 1500ms 동안 돈다. Map·Group은 새로고침 수단이 이 칸 하나뿐이다(Home·Custom은 처음부터 새로고침 버튼이 없다).

시장 시간대 칩을 누르면 시간 안내 팝업(달력과 같은 색)이 열린다. 안내문은 프리 08:00~08:50, 메인 09:00~15:30, 애프터 15:40~20:00, 그 외로 고정이고 서버 시간표나 지금 시간대와 연동하지 않는다. 칩 글자의 판정은 안내문과 따로 두었다. 프리 마켓은 메인 시작(09:00)까지, 메인 마켓은 애프터 시작(15:40)까지 칩에 보여서(서버 시간표가 있어도 같은 규칙) 08:50~09:00에는 칩이 프리 마켓, 15:30~15:40에는 메인 마켓으로 보인다. 이 두 구간은 안내문의 프리·메인 시간(08:50, 15:30)과 다르다.

종목·업종 검색창은 모든 Custom 화면(MARKETRY·거래소·내 분류)에서 제목 배지 오른쪽 윗줄에 둔다. 종목 표에서는 검색창 오른쪽 끝을 약칭 열 오른쪽 선에 맞추고, 입력은 12자까지다(분류 이름·약칭의 최대 길이와 같다). 검색은 대소문자·공백을 무시하고, 자음은 한글 글자의 초성으로 찾으며, 영문과 섞어 쳐도 된다. 종목명·약칭(관리자)·코드·분류명을 찾는다. 약칭은 백엔드도 12자 이하로 검증한다.

좁은 창에서 애프터 마켓의 왼쪽 묶음이 분류 배지를 5px 넘어가던 것은 누적/별도 토글 오른쪽의 음수 여백(-mr-[5px])을 없애 해결했다(이전 변경 전부터 있던 겹침이었다). 메인 영역이 왼쪽 묶음(약 584px)보다 좁아지면 분류 배지가 먼저 줄어들고, 그보다 더 좁아지면 가로로 넘친다(원래 설계).

## NXT 안내창과 종가·누적·별도 스위치 (2026-10-13)

지도 가운데 NXT 단독 시간대 안내창은 확인창과 같은 양식이다. 어두운 배경(지도만 덮고 클릭은 막지 않는다), 크림색 창, 굵은 제목(시간 범위), 본문 `NXT 종목만 표시 중 (n종목)`, `설정에 따라 달라질 수 있습니다.` 한 줄, 오른쪽 아래 청록 `닫기` 버튼이다. n은 서버가 준 NXT 종목 전체(제외 업종 포함)라서 지도에 실제로 그려지는 수보다 클 수 있다.

NXT 단독 시간대의 오전 구간은 08:00~09:00이다. 서버 시간표는 오전 구간을 단일가 접수 시작(08:50)에서 끝내지만, 08:50~09:00에는 체결이 없어서 정규장이 열리는 09:00까지 NXT 종목만 보여 준다. 안내창과 지도 필터가 같은 판정을 쓰므로 이 시간에는 필터도 NXT 종목만 남긴다. 오후 구간은 15:40~16:00 그대로다.

## 로딩 원을 하나만 돌린다 (2026-10-13)

홈은 틀 세 개마다 로딩·오류 원을 따로 그렸다. 지도·그룹·커스텀 페이지처럼 불러오는 중이나 오류일 때는 틀을 모두 감추고 메인 영역 가운데에 원 하나만 둔다. 기간 달력은 두 달이 각자 원을 돌렸는데, 두 달의 로딩을 합쳐 날짜 영역 가운데에 원 하나만 돌린다(월 이름·요일 줄 아래를 덮는다). 하루 달력은 한 달뿐이라 그대로다. 달력 안의 조회와 같은 쿼리 키로 부모에서도 로딩만 읽어서 요청은 늘지 않는다.

홈에도 지도·그룹 페이지와 같은 툴바와 아래 줄을 넣었다. 툴바 왼쪽에 제목 배지(`HOME` / `ALL STOCK`), 오른쪽 끝에 분류 배지를 두고, 아래 줄 왼쪽에 면책 문구, 오른쪽 끝에 등락률 바를 둔다. 이 요소들은 툴바와 아래 줄에 있어서 로딩 중에도 사라지지 않고 제자리에 있다(메인 영역의 로딩 원만 틀을 대신한다).

로딩 원 안의 경과 시간 숫자는 칸 한가운데보다 조금 위(`pb-[10cqw]`)에 둔다. 메인 영역의 큰 원은 숫자를 원 너비의 5.5%(11~24px)로 줄였고, 달력·설정창처럼 얇은 원은 7%(11~28px) 그대로다.

오류 문구("데이터를 불러오지 못했습니다.")와 로딩 안내 문구도 경과 시간 숫자와 같은 크기 규칙(원 너비의 5.5%, 11~24px)을 쓴다. 320px 원에서 17.6px이다.

오류 화면은 로딩 화면(안내 문구 없음)과 같은 로고 크기(원 너비의 84%)와 같은 아래 칸·여백(`pb-[10cqw]`)을 쓴다. 그래서 오류 문구가 경과 시간 숫자가 있던 바로 그 자리에 놓이고, 로딩에서 오류로 바뀌어도 로고가 움직이지 않는다. "다시 시도" 버튼은 문구 아래에 띄워 문구 위치를 밀지 않는다.

오류 화면의 "다시 시도" 버튼은 문구와의 간격을 8px에서 4px로 줄였다. 평소에도 강조색(`--brand`) 테두리·글자로 보이고, 마우스를 올리면 버튼 안을 강조색으로 채운다(글자는 검정).

로딩·오류 원 높이를 홈·지도·그룹·커스텀이 맞추도록 홈은 원이 보일 때 위 16px·아래 19.5px 여백(지도·그룹과 같다)을 쓰고, 커스텀의 로딩 화면은 아래 여백을 3.5px 더 둔다.

달력 오류도 로딩처럼 하나로 합쳤다. 기간 달력은 두 달 중 하나라도 못 받으면 달마다 "불러오지 못했습니다 다시 시도"를 따로 두지 않고, 로딩 원과 같은 자리(월 이름·요일 줄 아래 날짜 영역의 가운데)에 메인 영역과 같은 오류 원(로고 + "데이터를 불러오지 못했습니다." + "다시 시도")을 하나만 둔다. "다시 시도"는 실패한 달만 다시 받는다. 하루 달력도 같은 오류 원을 쓴다. 달력은 원이 작아(176px) `Spinner`의 `compact`로 테두리를 얇게, 로고를 60%로, 버튼을 작게 그린다.

"다시 시도" 버튼을 더 작게 줄였다. 메인 영역은 글자 12px·좌우 12px·상하 2px 여백(이전 14px·16px·6px), 달력은 글자 11px·좌우 8px·상하 1px 여백이다.

"다시 시도" 버튼 글자는 굵게(`font-semibold`) 한다.

"다시 시도" 버튼은 문구 아래 간격을 버튼 높이의 반만큼 더 늘렸다(메인 영역 4px → 15px, 달력 4px → 13px). 달력은 버튼이 원 아래 곡선에 닿지 않도록 오류 원을 176px에서 184px로, 로고를 60%에서 56%로 줄였다.

달력의 로딩·오류 원은 월 이름·요일 줄까지 덮고 가운데에 하나만 둔다(하루 달력은 달력 한 달 전체, 기간 달력은 두 달 전체). 로딩과 오류의 원 크기(184px)와 로고 크기(56%)를 같게 해서 서로 바뀌어도 움직이지 않는다. 메인 영역의 큰 원이 기준이고, 달력은 같은 구성(로고·문구·숫자·버튼)을 작게 줄인 모양이다.

로딩·오류 원의 모든 크기를 원 너비에 대한 비율로 통일했다(테두리 1.9%, 로고 84%, 문구·숫자 5.5%, 버튼 글자 3.75%·좌우 여백 3.75%·상하 여백 0.6%, 문구와 버튼 사이 4.7%, 숫자·문구 아래 여백 10%). 메인 영역의 320px 원이 기준이라 달력처럼 작은 원도 같은 비율로 줄어든다. 이전에는 달력만 로고 56%·글자 11px 이상 등 따로 정한 값이라 비율이 맞지 않았다. 그래서 `Spinner`의 `compact` 옵션을 없앴고, 달력의 원은 한 달 달력 안에 들어가는 최대 크기(232px)로 키웠다. 설정창의 얇은 원(`showLogo`)은 그대로다.

오류 문구("데이터를 불러오지 못했습니다.")는 흰색으로 그린다(로딩 숫자는 회색 그대로). "다시 시도" 버튼은 좌우 여백을 원 너비의 3.75%에서 2.2%로 줄이고 글자를 `font-bold`로 더 굵게 했다.

"다시 시도" 버튼의 평소·마우스 올림 모양을 서로 바꿨다. 평소에는 안이 강조색(`--brand`)으로 채워진 검정 글자이고, 마우스를 올리면 안이 비고 강조색 테두리·글자가 된다.

설정창의 로고 원(`showLogo`)도 같은 비율(테두리 1.9%, 숫자 5.5%)을 쓰게 해서 `Spinner`의 얇은 모양 분기를 없앴다. 공유 창의 미리보기 이미지를 만드는 동안에도 작은 링 대신 큰 로고 원(경과 시간 포함)을 보여 준다. 버튼 안이나 저장 칸 옆처럼 수십 px의 작은 링은 글자가 읽히지 않아 그대로 둔다.

오류 화면의 문구와 "다시 시도" 버튼은 경과 시간 숫자 자리보다 원 너비의 2%(320px 원에서 6.4px) 위에 둔다(아래 여백 10% → 14%).

경과 시간 숫자의 아래 여백도 오류 문구와 같은 14%로 올려서, 로딩의 숫자와 오류의 문구가 같은 높이에 온다(둘 다 이전보다 원 너비의 2%만큼 올랐다). 문구와 숫자는 같은 칸 안에서 가운데 정렬이라 글자 한 줄의 가운데가 같다.

"다시 시도" 버튼을 조금 키웠다: 글자 3.75% → 4.25%, 좌우 여백 2.2% → 2.6%, 상하 여백 0.6% → 0.8%, 문구와의 간격 4.7% → 5%(원 너비 기준). 320px 원에서 글자 13.6px·버튼 약 24px 높이, 232px 원에서 글자 9.9px·약 17.6px 높이다.

Custom의 로딩 화면(세션·분류 목록을 받는 동안)은 원이 설정창을 뺀 메인 영역의 한가운데에 오게 했다. 설정창이 열려 있으면 그 너비(288px, `w-72`)만큼을 빈 칸으로 비워 두고, 설정창을 왼쪽으로 옮겼으면 빈 칸도 왼쪽에 둔다. 설정창을 접었으면 화면 전체의 가운데다. 그래서 지도·그룹 페이지의 로딩 원과 가로 위치가 같다.

MARKETRY 종목 표(`AdminStockTable`)에 로딩·오류 원을 넣었다. 이 표의 `isPending`은 정렬 전환용(`useTransition`)이고 종목 목록을 처음 받는 중에는 로딩 표시가 없어 "데이터 없음"이 잠깐 보였으며, 받지 못해도 빈 표만 남았다. 이제 목록을 받는 중에는 다른 페이지와 같은 로딩 원, 받지 못했으면 같은 오류 원(문구와 "다시 시도")을 표 자리에 보여 주고, 빈 표 문구는 로딩·오류 중에 감춘다.

## Custom의 로딩 원 위치와 설정창이 사라지던 문제 (2026-10-14)

Custom 페이지에서 로딩 원이 지도·그룹 페이지와 다른 자리에 떴고, 로딩이 길어지면 설정창이 사라졌다가 다시 생겼다. 원인은 둘이었다.
- 세션·분류 목록을 받는 동안 페이지 전체를 상단바와 원만 있는 별도 화면으로 바꿔서(`isSessionLoading || (isLoggedIn && isSectorsLoading)`) 설정창이 아예 없었고, 로딩이 끝나면 설정창이 새로 생겼다. 이제 그 화면을 없애고 본문 자리에만 원을 둔다. 상단바·툴바·설정창은 로딩 내내 그대로다.
- 내 분류 종목 표(`AdminStockTable`)는 종목 목록을 받는 동안 원을 표 안의 한 줄(높이 32rem)에 넣어서 표 머리글 아래 위쪽에 떴다. 이제 로딩·오류일 때 표 대신 본문 한가운데에 원을 둔다(마켓트리·거래소 표와 같다). 정렬을 바꾸는 동안의 원은 표 안에 그대로 있다.

Custom의 본문 로딩·오류 원 여백은 지도·그룹 페이지와 같은 높이가 되도록 위 16px·아래 47.5px(지도·그룹의 아래 19.5px + Custom에는 없는 아래 줄 28px)로 통일했다. 헤드리스 브라우저로 API 응답을 6초 붙잡고 재 보니 홈·지도·그룹·Custom(MARKETRY·거래소·내 분류 종목)의 로딩 원 중심이 모두 같은 자리(2000×1000 화면에서 가로 856, 세로 546)이고 설정창이 계속 보였다.
## 선택 버튼(Basis 등)의 구분선이 이동 중에 끊어져 비치던 문제 (2026-10-14)

홈 세 틀 제목 배지를 청록이 아니라 흰 바탕에 검정 바·검정 글자로 바꿨다(청록은 아래 줄의 배지들과 같아 제목이 묻혔다).

홈 세 틀 제목 배지의 글자 오른쪽 여백을 12px에서 바 왼쪽 여백과 같은 8px로 줄였다.

그룹 등락률 틀의 오른쪽 칸([등락수 배지][▲N ▼N ■N])이 창이 좁을 때(1280px 화면에서 틀 폭 약 326px) 잘리던 것을 고쳤다 — 오른쪽 칸은 안의 글자 폭보다 줄지 않고, 왼쪽 칸(단계 배지 하나)이 대신 줄어든다. 넓을 때는 지수 줄처럼 두 칸이 같은 폭이다.
## 오류 원에서 문구를 없애고 "다시 시도" 버튼만 둔다 (2026-10-14)

불러오지 못했을 때의 오류 원은 "데이터를 불러오지 못했습니다." 문구와 그 아래 "다시 시도" 버튼 대신, 로딩 때 경과 시간 숫자가 있던 자리에 "다시 시도" 버튼만 둔다(원에 로고 + 버튼). 문구가 없어도 원이 멈춰 있고 버튼이 있어 뜻이 통한다는 판단이다. 오류 문구는 스크린 리더용 `aria-label`로만 남기고, `onRetry`가 없는 곳은 버튼이 없어 알 수 없으므로 그때만 문구를 보여 준다(지금 모든 호출부는 `onRetry`가 있다). 버튼 색은 설정창 "적용"·확인 팝업 버튼과 같다. 요청 제한 시간(timeout)이 없어 서버가 응답을 아예 안 주면 숫자만 계속 올라가는 점은 그대로다.

홈 세 틀 제목 배지는 가운데가 아니라 왼쪽 끝에 붙여 둔다(이전에는 가운데 정렬).

홈 시장 요약·그룹 등락률 틀의 제목 줄과 둘째 줄을 한 격자(같은 폭의 두 칸, 간격 8px)로 짰다. 칸의 크기·모양·너비는 이전 한 줄 배치 그대로이고 위치만 바뀐다 — 코스피(그룹 등락률은 단계 배지 "대분류")가 코스닥("등락수") 위, 곧 제목 줄의 오른쪽 칸으로 올라가 제목 오른쪽에 서고, 코스닥(등락수)은 원래 자리(오른쪽 칸) 그대로 둘째 줄에 있다. 둘째 줄의 왼쪽 칸은 비어 있다. 코스닥을 아래로 내리지 않아 틀이 한 줄 늘지 않는다. 제목 줄 28px·둘째 줄 24px이다. 그룹 등락률의 오른쪽 칸은 창이 좁아도 안의 글자 폭보다 줄지 않는다.

홈 세 틀의 안쪽 좌우 여백은 양 끝(첫 틀 왼쪽·마지막 틀 오른쪽)은 0으로 두고 틀 사이(구분선 양옆)에만 8px 둔다. 여백은 틀이 아니라 틀 안쪽 칸에 둬서 세 틀의 너비는 같다.

홈 세 틀의 위아래 안쪽 여백을 없앴고, 전체 외곽선도 없애 틀 사이의 세로 구분선만 점선(gray-700 dashed)으로 남겼다.

홈 세 틀 사이의 점선 구분선도 없앴다(외곽선은 이미 없음) — 이제 틀 사이에 선이 없다. 툴바 아래 여백(5.25px)만큼 틀을 위로 붙여 툴바와 틀 사이, 틀과 맨 아래 줄 사이에 여백이 없다.

홈 세 틀의 맨 윗줄 위 여백은 커스텀 페이지의 표와 같은 값(툴바 아래 여백 5.25px)으로 되살렸다(직전에 이 여백을 위로 당겨 없앴었다).

단계 배지("대분류")는 그룹 등락률 틀에서 빼서 시장 요약 틀의 제목 아래(둘째 줄 왼쪽, 코스닥 왼쪽의 빈 자리)로 옮겼다.

"대분류" 배지 색을 "등락수" 배지와 같은 짙은 청록(cyan-900)으로 맞췄다.

"코스닥" 배지 색을 "코스피" 배지와 같은 청록(cyan-700)으로 맞췄다(이전에는 코스닥만 짙은 청록).

"등락수" 배지를 "코스피"·"코스닥" 배지와 같은 청록(cyan-700)으로 바꿨다(이전에는 짙은 청록). "대분류" 배지는 짙은 청록(cyan-900) 그대로 둔다.

툴바 시각 칩은 칩 전체가 새로고침 버튼이다. 평소에는 시계·시각 글자가 보이고, 커서를 올리거나 키보드 포커스가 오면 글자 자리(칩 한가운데, 시와 분 사이 콜론 자리)에 청록 새로고침 아이콘이 나타나며, 누르면 새로고침하고 아이콘이 1500ms 돈다. 칩 폭은 글자가 자리를 계속 차지해 변하지 않는다. 별도의 새로고침 아이콘 칸은 없앴다. 지도·그룹·홈 툴바가 같다. (옛 "호버 시 새로고침 아이콘으로 바뀜" 동작을 되살린 것이다.)

홈 세 틀 제목은 흰 배지가 청록 배지들 사이에서 너무 튀어서 배지를 빼고 흰 바 + 흰 글자 헤더로 바꿨다.

## 홈 틀 재배치 (2026-10-14)

홈 세 틀의 순서는 시장 요약, 시장 지도, 그룹 등락률이다. 옛 "안내" 틀이 "시장 요약"이 되어 맨 왼쪽으로 갔고, 옛 "시장 요약"은 "시장 지도"로 이름을 바꿨다. 지수·등락수 배지는 시장 지도·그룹 등락률 틀에서 빼서 시장 요약 틀 맨 위로 옮겼다(대분류 배지는 삭제). 위에서부터 코스피·코스닥(지수, 전일 대비 포인트, 등락률) → 등락수(▲·▼·■) → 거래대금(코스피·코스닥·전체) → 빈 줄 → 신규 상장 이하 안내 종목이다. 틀 안 글자는 14px, 배지는 모서리가 각진 직사각형이다. 틀 사이 간격은 24px이다. 지수·등락수 줄의 숫자는 칸 폭을 정해 숫자 끝을 오른쪽으로 맞추고 값 묶음은 왼쪽 4px 여백에서 시작한다.

## 팝업을 확인창·알림창·안내창으로 나누고 배지를 붙였다 (2026-10-14)

팝업 종류는 **확인창**(`확인`/`취소`로 답해야 함, 청록 "확인" 배지), **알림창**(꼭 읽고 `닫기`, 호박색 "알림" 배지), **안내창**(지나가도 되는 알림, 회색 "안내" 배지)과 별개의 **캡처 창**이다. 확인창·알림창은 화면 전체를 어둡게 덮고 뒤 화면 클릭을 막으며, 안내창은 배경 없이 뒤 화면을 그대로 쓴다(NXT 안내창의 어두운 배경은 이 규칙에 맞춰 뺐다).

배지 이름은 처음 "결정"이었다가 "확인"으로 바꿨다. 확인·취소 버튼으로 끝나는 창이고 코드의 `appConfirm`·`confirm`과도 맞기 때문이다. "알림"과 "안내"는 말이 비슷하지만 알림창이 꼭 읽어야 하는 쪽이다. 제목은 "대상 + 동작"으로 짧게 쓴다(업종 삭제, 버전 불러오기, 색상 초기화). 업종 이름·버전 시각은 `[ ]`로 감싼다. 모든 팝업은 폭 384px, 높이 198px(본문 3줄)로 통일하고 3줄을 넘으면 늘어난다(`POPUP_SIZE_CLASS`). 운영자용 확인창은 빨간 테두리·제목·⚠로 구분하고 ADMIN 전용 띠는 뺐다. 문구는 가능하면 3줄 이내로 줄인다(엑셀 적용은 개수만 한 줄 요약).

규칙 원문은 `docs/ui-areas.md`의 "팝업 규칙"이고, 확정된 이미지는 드라이브 `규칙 ★/팝업`에 둔다(최종본만, 버전 표기 없이 같은 이름으로 덮어쓴다).

## 마우스 올림 설명을 data-hint 한 방식으로 통일했다 (2026-10-14)

## 업종 단계는 3단계가 기본이다 (2026-10-14)

업종 단계 이름은 대분류 · 중분류 · 소분류 · 세분류다. 지금은 3단계(대·중·소분류)만 쓰고, 4단계(세분류)는 이름만 정해 뒀으며 거의 만들지 않을 예정이다. 이달 말 거래소가 새 업종 분류를 발표하면 그것을 보고 최종 정한다. 5단계 이상은 지도 위에서 자리가 모자라 만들지 않는다. 이동 경로 툴팁이 이 단계 이름을 쓴다(`대분류로 돌아가기`).

## 위치·동작으로 설명하는 지시를 이름으로 해석한다 (2026-10-14)

## 설정창·상단 아이콘과 "스크린샷" 용어를 정리했다 (2026-10-14)

- 용어: "캡처"를 "스크린샷"으로 바꿨다(상단 버튼 이름·툴팁 "스크린샷 찍기", 창 제목 Screenshot, 오류 문구, 주석·문서). 코드 이름도 `CaptureModal`→`ScreenshotModal`, `captureRef`→`screenshotRef`처럼 바꿨다. 백엔드 렌더러와 맞춘 화면 표식(`data-captureid`·`data-capture-ready`·`data-capture-ignore`, `CAPTURE_ID`·`captureIds.ts`)은 계약이라 그대로 둔다.
- 설정창 저장·되돌리기: 틀 없이 아이콘만 두고(상단 아이콘과 같은 방식), 되돌리기는 시계 화살표, 저장은 좌우 대칭 디스켓으로 바꿨다. 크기는 18px, 선 굵기는 상단 아이콘과 같은 약 1.33px이고 위치는 맨 위 줄 오른쪽이다. Basis 줄 오른쪽·가운데 배치도 써 봤으나 맨 위 오른쪽이 설정 전체에 적용되는 버튼 자리로 맞아 유지했다.
- 상단 아이콘: 스크린샷은 점선 사각형(24px), 전체화면은 확장 화살표, 설정은 바퀴살 톱니로 바꿨다. 아이콘 사이 간격(10px)과 가로 위치를 설정창 아이콘과 맞췄고, 세 아이콘에 툴팁을 달았다.
- 배지: 확인·알림·안내 배지와 설정창 종목 배지를 우클릭 팝업 배지와 같은 높이(18px)·굵기(`semibold`)로 맞췄다.
- 선택 버튼 구분선: 애프터 버튼과 같은 규격(1px 회색, 묶음 높이의 42%)으로 두고 선택 칸 옆은 숨긴다.
- 툴팁: 새로고침 아이콘도 `data-hint`로 합쳤다. 애프터 토글은 굵은 글씨·빨간색이 있어 개별 구현으로 남겼다.

## SettingsSidebar를 SettingsPanel로 바꿨다 (2026-10-14)

홈 틀을 지도 페이지 높이에 맞췄다(지도 페이지가 기준). 틀 제목을 16px 세미볼드에서 지도 섹터 헤더와 같은 15px 굵게로, 제목 줄을 28px에서 18px로 줄이고 제목 줄과 본문 사이 4px을 없앴다. 그래서 세 틀의 본문이 모두 제목 줄 바로 아래에서 시작하고, 시장 지도 틀의 맨 위가 지도 페이지의 첫 종목 박스와 같은 높이가 됐다(1500×900과 1920×1000 화면에서 헤더 124~142px, 본문 시작 142px로 재서 확인). 틀 안 내용과 세로 높이 계산은 그대로다. 위 괄호 속 "28px/4px" 같은 옛 수치는 이전 기록이다.
틀 제목 글자도 지도 섹터 헤더처럼 왼쪽에서 4px 들여썼다(`pl-1`, 지도 헤더 버튼의 `px-1`과 같다).

## 선택 버튼 채움을 left로 옮긴다 (2026-10-15)

운영 사이트를 웨일 브라우저로 보면 Basis 선택 버튼 묶음의 양 끝에 가는 세로선이 화면 배율에 따라 생겼다 사라졌다. 개발자 도구로 보면 묶음 안에는 채움 `span` 1개와 버튼 3개뿐이고 선을 그리는 요소·테두리는 없었다. Chrome과 Orca 브라우저에서는 여러 배율(1~1.75)로 봐도 재현되지 않았다. 원인은 확정하지 못했고, 채움을 `transform: translateX`로 옮기면 별도 합성 층이 생겨 웨일에서만 이음새가 비치는 것으로 의심했다. 그래서 `SlidingHighlight`가 채움을 `left`(`transition-[left]`)로 옮기게 바꿨다. 겉모양과 500ms 미끄러짐은 그대로다. 선이 계속 보이면 웨일 자체 기능(빠른 검색 등)이 그리는 것으로 보고 우리 코드는 더 바꾸지 않는다.

## 선택 버튼 틀을 직각으로 바꿨다 (2026-10-15)

웨일 브라우저에서 하드웨어 가속을 켜면 Basis 등 선택 버튼 묶음의 양 끝 안쪽에 가는 세로선이 비쳤다(가속을 끄면 사라짐, 크롬·Orca에서는 없음). 개발자 도구에서 선택 칸 채움·버튼·틀 배경을 하나씩 숨겨 보니 선은 밝은 회색 틀(`rounded-lg bg-[var(--accent)]`)의 배경에서 나왔다. 틀 모서리를 직각으로 바꾸면 사라졌고, 배경을 그라데이션이나 안쪽 그림자로 칠해도 둥글면 남았다. 그래서 선택 버튼 묶음 틀 9곳(`SettingsPanel`)과 날짜 선택창의 `선택 방식` 틀의 `rounded-lg`를 뺐다. 선택 칸 채움과 버튼의 5px 모서리는 그대로다. 앞서 채움을 `left`로 옮긴 변경(PR #267)은 효과가 없었지만 그대로 둔다. 틀 모양을 아예 다시 디자인하는 시안은 따로 받기로 했다.

## 선택 버튼을 칸마다 떨어진 칩으로 바꿨다 (2026-10-15)

시안 3장(드라이브 `marketry/설정창-선택버튼-시안1장(1943)`·`2장(1945)`·`3장(1948)`)을 비교하다가 1-D(밝은 직각 틀)를 골랐지만 곧 1-F(분리된 칩)로 바꿨다. 설정창 선택 버튼 9곳은 이제 큰 틀 배경 없이 칸마다 떨어진 칩 3개(간격 6px, 모서리 5px, 바탕 `#4b4b50`)이고, 선택 칸의 채움이 칩 사이를 미끄러진다(500ms). 선택 채움은 Basis만 청록(`bg-cyan-700`, 흰 글자), 나머지는 슬라이더 선과 같은 밝은 회색(`bg-[var(--accent)]` = `#d1d5db`, 검은 글자)이다. 미선택 글자는 `zinc-200`이다. 칩 바탕과 채움은 `SlidingHighlight`가 그리므로 묶음 쪽에는 `gap-[6px]`만 둔다(틀 배경·안쪽 여백 없음). 전종목 도움말 아이콘은 미선택 칩에서 밝게, 선택 채움에서 진하게 표시한다. 날짜 선택창의 `선택 방식` 틀은 밝은 팝업 안에 있어 이번에 바꾸지 않고 직각 틀로 남겼다. 웨일(가속 켬)에서 가는 세로선이 없는지는 배포 뒤 직접 확인이 필요하다.

지도 윗줄(툴바)의 애프터 버튼(종가·누적·별도)도 같은 칩 모양으로 바꿨다. 틀 없이 칩 3개(간격 3px, 칸 폭 약 38px, 높이 24px)이고 선택 칸의 보라색 채움이 칩 사이를 미끄러진다. 지도 윗줄은 모서리가 직각이라 이 버튼의 칩도 직각이고(`SlidingHighlight`의 `square`), 설정창 안은 둥근 모서리(5px) 그대로다. 채움 위치는 버튼 크기를 재지 않고 `SlidingHighlight`가 칸 폭의 배수로 계산한다.

## 종목 박스 이름을 말줄임표 없이 박스에 맞춘다 (2026-10-15)

종목 박스 이름은 `text-clip`이라 박스보다 길면 끝이 말줄임표 없이 잘렸고(삼성바·LG에너 같은 반쪽 이름), 글자 크기도 박스 크기로만 정해져 이름 길이를 보지 않았다. 사용자는 **말줄임표는 무조건 반대**라서, 잘리는 글자 대신 박스에 맞추는 방식으로 바꿨다(`utils/stockLabelFit.ts`, 시안은 드라이브 `marketry/종목박스-글자잘림-시안1장(2017)`의 1-4+1-3+1-5 조합).
- 이름이 한 줄에 들어가면 그대로 둔다.
- 안 들어가면 **두 줄**로 나눈다(긴 줄이 가장 짧아지는 자리, 공백이 있으면 공백 먼저). 영문·숫자·기호 한 덩어리(E1, OCI, F&F)는 줄 안에서 쪼개지 않는다.
- 두 줄로도 안 들어가면 글자를 **10px까지** 0.5px씩 줄여 본다. 한 줄이 아니라 "두 줄까지 허용"하는 가장 큰 크기를 고른다.
- 10px에서도 안 되면 이름을 감추고 **등락률만 가운데**에 둔다. 등락률도 폭에 안 들어가면 10px까지 줄이고, 그래도 안 되면 아무것도 그리지 않는다.
글자 폭은 canvas로 한 번만 재서(글자 100px 기준, 크기에 비례) 박스 수백 개여도 가볍고, 글꼴(Pretendard)이 늦게 로드되면 다시 계산한다. 설정창의 박스 내 표기(이름만·등락률만·둘 다)와 표시 기준은 그대로다. 이름만 고른 경우 이름이 안 들어가면 아무것도 그리지 않는다. 두 줄로 나눌 때 3글자 이름은 윗줄 1글자 + 아랫줄 2글자(예: 카/카오), 2글자 이름은 1글자씩(예: 후/성)이다. 최소 글자 크기는 처음 9px, 8px로 내려 보니 너무 작아 쓸 수 없다고 해서 최종 10px로 정했다.

종목 박스 이름의 줄바꿈 자리는 사용자 요청으로 **뜻이 갈리는 곳 우선**으로 바꿨다(`stockLabelFit.ts`). 순서는 (1) 공백 (2) 영문·숫자·기호와 한글의 경계(LG/이노텍, BNK/금융, DB/손해보험)와 그룹사 이름 뒤(한화/비전, 삼성/전기, 롯데/쇼핑, 포스코/퓨처엠, HD현대/건설기계) 중 긴 줄이 가장 짧아지는 자리 (3) 아무 자리. 폭이 같으면 윗줄이 더 길다(테크/윙). 영문·숫자·기호 덩어리(E1, OCI, F&F)는 나누지 않는다. 뜻 갈리는 자리가 있는 이름은 글자를 10px까지 줄여서라도 그 자리에서 나누고, 10px로도 안 되면 아무 자리에서 나눈다. 그룹사 이름은 `GROUP_PREFIXES`(삼성·현대·롯데·한화·두산·포스코·한진·효성·카카오·에코프로·미래에셋·한국·아시아나 등) 목록이고, 새 그룹명이 필요하면 이 목록에 더한다.

종목 박스 이름의 줄바꿈에 **접미어 규칙**을 더했다(`suffixSplitPosition`). 우선주(`…우`, `…우B`, `…2우B`)와 지주사(`…지주`, `…지주회사`, `…홀딩`, `…홀딩스`)는 접미어 앞에서 나눈다(삼성전자/우, 현대차/2우B, 신한/지주, 우리금융/지주, 한화/홀딩스). 앞부분이 2글자 이상일 때만 접미어로 보고("대우"는 그대로), 접미어 자리가 폭에 안 들어가면 글자를 10px까지 줄여 보고, 그래도 안 되면 그룹명·영문 경계·아무 자리 순으로 넘어간다. 줄바꿈 우선순위는 접미어, 공백, 영문·한글 경계와 그룹명 뒤, 아무 자리 순이다.

종목 박스 글자 규칙을 세 가지 더 다듬었다(`stockLabelFit.ts`).
- **글자 수 차이**: 공백이나 그룹명 뒤에서 나눴을 때 두 줄의 글자 수 차이가 3 이하(`MAX_WORD_SPLIT_DIFF`)일 때만 그 자리에서 나누고, 차이가 더 크면 균형 있게 나눈다(롯데에너지/머티리얼즈, 삼성바이/오로직스). 접미어(우·지주·홀딩스)는 차이와 상관없이 접미어 앞에서 나눈다.
- **영어/한글 경계**: 영문·숫자·기호와 한글이 만나는 자리(영어/한글, 한글/영어: LG/이노텍, BNK/금융, DB/손해보험)는 글자 수 차이와 상관없이 항상 후보에 둔다.
- **기업명 우선**: 종목명과 등락률이 함께 안 들어가면 등락률을 빼고 **이름만** 보여 주고, 이름이 안 들어갈 때만 등락률만 보여 준다(이전에는 둘이 안 들어가면 이름까지 감추고 등락률만 보여 주던 경우가 있었다).

## 다른 종목과 겹치는 약칭은 저장하지 않는다 (2026-10-15)

약칭은 운영자만 정하지만(유저 약칭은 일부러 막아 둠), 운영자가 정한 약칭이 다른 종목의 이름과 같아지면 지도에서 서로 다른 종목이 같은 이름으로 보인다. 실제로 `381970 KG모빌리티플랫폼`의 약칭이 `KG모빌리티`라서 `003620 KG모빌리티`와 똑같이 보였다. 그래서 종목 표에서 약칭을 저장하기 전에 표 전체와 견줘(`utils/aliasConflict.ts`, 대소문자·공백 무시, 자기 자신은 제외) 다른 종목의 이름이나 약칭과 같으면 저장하지 않고 안내창(운영자 전용 경고색)으로 겹치는 종목을 알려 준다. 이미 저장된 겹치는 약칭은 자동으로 바뀌지 않으므로 해당 약칭을 직접 고치거나 지워야 한다. 백엔드(`CustomStockSectorService`)에는 같은 검증이 아직 없다(관리자만 호출할 수 있어 화면 검증만 두었다).

우선주 접미어는 사용자 요청으로 **표시가 분명한 것만** 앞에서 나누도록 좁혔다(`suffixSplitPosition`). `1우B`·`2우B`·`3우B`·`우B`는 앞에서 나누고(현대차/2우B, 삼성물산/우B), 맨 끝이 그냥 `우`인 이름은 떼지 않는다(삼성전자우는 삼성/전자우처럼 이름 규칙대로 나눈다). 지주사 접미어(`지주`·`홀딩스`)는 그대로다. 그룹명 목록에 `파마`·`서진`·`셀트리온`·`경동`·`비에이치`를 더했다(파마/리서치, 서진/시스템, 셀트리온/제약, 경동/나비엔, 비에이치/아이).

종목 박스 이름은 **한 줄에 들어가면 나누지 않는다**는 사용자 요청으로, 두 줄로 나누기 전에 글자를 `ONE_LINE_MIN_FONT`(11px)까지 줄여 한 줄에 맞춰 본다(`stockLabelFit.ts`). 한 줄에 들어가면 그 크기로 한 줄이고(한화비전·삼성전기·신한지주), 11px로도 안 들어갈 때만 두 줄로 나눈다. 두 줄로 나눈 뒤에는 이전과 같이 글자를 10px까지 줄여 보고, 그래도 안 되면 이름을 감추고 등락률만 보여 준다. 11px 한계는 한 줄에 억지로 맞추다 글자가 너무 작아지는 것을 막으려는 값이라 바꿔 볼 수 있다.

종목 박스에서 **이름이 안 들어가면 등락률만 남기지 않는다**(사용자 요청). 이름과 등락률 중 하나만 들어가야 하면 종목명이 우선이라 등락률을 빼고 이름만 보여 주고, 이름이 안 들어가면 이름과 등락률 모두 그리지 않는다. 설정에서 "등락률만"을 직접 고른 경우에만 등락률만 보여 준다(`fitStockLabel`).

종목 박스 이름 글자 크기의 **상한을 22px에서 30px로 올렸다**(`StockBox.fontSizePx`). 글자 크기는 박스 짧은 변 ÷ 5이고(최소 12px), 상한은 짧은 변이 150px 이상일 때부터 걸린다. 그래서 삼성전자·삼성전자우·SK스퀘어 같은 큰 박스만 커지고 나머지 박스는 그대로다(등락률은 이름의 85%라 최대 25.5px). 시안은 드라이브 `marketry/종목박스-글자상한-시안2장-1~5`(22·25·28·30·34px)이고 사용자가 30px(2-4)를 골랐다.

종목 박스 줄바꿈에 **한글로 읽어 쓴 알파벳 사명** 규칙을 더했다(`letterClusterBoundaries`). 이름 맨 앞에서부터 한글 알파벳 이름(에이·비·씨·디·이·에프·지·에이치·아이·제이·케이·엘·엠·엔·오·피·큐·알·에스·티·유·브이·더블유·엑스·와이·제트)이 **2개 이상** 이어지면 한 묶음으로 보고, 묶음의 한 글자(에이치, 케이 등) 안에서는 나누지 않으며(에이/치엘비가 아니라 에이치/엘비), 묶음이 끝나는 자리를 그룹명 뒤와 같이 후보로 쓴다(케이씨/텍, 엔씨/소프트, 에스케이/하이닉스, 에이치디/현대, 비에이치/아이, 엘지/에너지). 글자가 1개뿐인 이름(에이스침대, 아이센스, 알테오젠)은 건드리지 않는다.

종목 박스 줄바꿈에 **끝 단어 목록**을 더했다(`DESCRIPTOR_WORDS`, `descriptorSplitPosition`). 이름 끝이 흔한 기업·업종 단어(테라퓨틱스, 노믹스, 게임즈, 데이타, 네오룩스, 시스템, 솔루션, 글로벌, 바이오, 제약 등)와 맞고 앞부분이 2글자 이상이면 그 단어 앞에서 나눈다(인제니아/테라퓨틱스, 온코닉/테라퓨틱스, 알지/노믹스, 넥슨/게임즈, 다우/데이타, 덕산/네오룩스, 선익/시스템). 그룹명 뒤와 같이 두 줄의 글자 수 차이가 3 이하일 때만 쓰고, 이름 끝과 맞는 가장 긴 단어 하나만 본다. 회사 이름을 하나씩 적지 않아도 되도록 둔 목록이라, 빠진 단어는 이 목록에 더한다.

## 확인창·알림창 뒤의 막힌 곳을 누르면 소리와 흔들기 (2026-10-15)

확인창·알림창(`AppDialogHost`)은 화면을 어둡게 덮고 뒤 화면 클릭을 막지만, 막힌 곳을 눌러도 아무 반응이 없어 "왜 안 눌리지" 싶을 수 있다. 윈도우 네이티브 대화창처럼 **창 바깥을 누르면 짧은 "딩" 소리를 내고 창을 0.32초 동안 좌우로 살짝(약 7px) 흔든다**. 창 안쪽(버튼·글자)을 누르면 반응하지 않는다. 소리는 음원 파일 없이 Web Audio로 만든 종소리 모양(1175Hz + 배음 2350Hz, 0.25초에 걸쳐 사라짐)이고(`utils/dialogSound.ts`), 연타해도 0.3초에 한 번만 난다. 윈도우의 진짜 시스템 소리는 웹에서 낼 수 없어 비슷한 톤이다. 운영체제에서 "움직임 줄이기"를 켜 두면 흔들지 않고 소리만 낸다. 배경을 눌러도 창이 닫히지는 않는 기존 동작은 그대로다(버튼이나 Esc로만 닫힌다). 소리를 끄는 설정은 아직 없다.

## 팝업에서 글자 드래그 선택과 이미지 끌기를 막는다 (2026-10-15)

팝업 안의 제목·본문을 마우스로 끌면 글자가 선택되고, 스크린샷 창의 미리보기 이미지를 끌면 브라우저 기본 동작으로 이미지가 따라 끌려갔다. 팝업을 옮기는 기능은 원래 없어서(창 이동 없음) 두 가지만 막았다. 확인창·알림창(`AppDialogHost`), 스크린샷 창(`ScreenshotModal`, 이미지는 `draggable={false}`), 로그인 창(`LoginModal`), 우클릭 메뉴·커서 툴팁(`Popup`), NXT 안내창(`MapPage`)에 `select-none`을 달고, 창 안에서 시작한 끌기(`dragstart`)는 취소한다. 입력창이 있는 팝업이 없어서 글자 입력에는 영향이 없다. 팝업 글자를 복사할 수는 없게 된다.

끝 단어 목록에 `코리아`를 더했다(펌텍/코리아).

## 홈 시장 지도: 업종명 두 줄 나눔과 등락률 크기 (2026-10-15)

홈 시장 지도(`OverviewMap`)는 거래소 모드에서 업종명이 길고 `/`가 들어가(음식료/담배, 운송/창고, 전기/가스, 의료/정밀기기) 좁은 박스에서 "음식료/", "전기/"처럼 뒤가 잘려 보였다. 그래서 이름이 12px로도 한 줄에 안 들어갈 때 `/`(없으면 공백) 자리에서 **두 줄로 나눈다**(`utils/overviewLabel.ts`). 슬래시는 아랫줄 앞에 둔다(윗줄 `음식료`, 아랫줄 `/담배`). 한 줄에 들어가면 나누지 않고, 두 줄 높이도 안 되면 한 줄 그대로 둔다. 두 줄에 등락률까지 안 들어가면 등락률을 뺀다(이름 먼저). 이름은 숨기지 않는다. 종목 박스용 목록(그룹명·끝 단어 등)은 쓰지 않는다. `/`나 공백이 없는 이름(임의소비재, 일반서비스)은 좁으면 지금처럼 가장자리에서 잘린다.

등락률은 이름의 70%(최소 12px)였는데, 이름이 12~17px인 박스는 숫자가 전부 12px로 똑같아 "업종명에 비해 작고 균일하다"는 지적이 있어 **이름의 90%**(최소 12px)로 올렸다(이름 28px → 숫자 25px, 20px → 18px, 16px → 14px). 글자 크기 상한(약 28px)은 그대로다.

홈 시장 지도에서 **두 줄로도 안 들어가면 이름과 등락률을 모두 빼기로 했다**(사용자가 "너무 잘리면 아예 빼자"). 한 줄은 박스에 맞는 크기에서 12px까지 줄여 보고, 안 되면 `/`·공백 자리에서 두 줄로 나눠 같은 방식으로 맞추고, 그래도 안 되면(또는 높이가 모자라면) 이름도 등락률도 그리지 않는다. 이름과 등락률 중 하나만 들어가야 하면 이름이 먼저다. 글자 폭은 글자 수 어림 대신 canvas로 직접 재서(`utils/overviewLabel.ts`, 글꼴이 늦게 로드되면 다시) 판단한다(영문이 섞인 "IT 서비스" 같은 이름이 실제보다 넓게 계산돼 빠지는 일을 막는다). 등락률도 폭에 안 들어가면 12px까지 줄이고 그래도 안 되면 뺀다. 앞에 적은 "이름은 숨기지 않는다"와 "좁으면 잘린다"는 이 결정으로 바뀌었다.

홈 시장 지도(`OverviewMap`)에 **마우스 올리면 뜨는 업종 팝업**과 **마우스 올림 색 변화**를 더했다. 처음에는 지도 페이지처럼 우클릭 팝업으로 만들었는데, 홈 지도가 작아서 사용자가 "우클릭보다 올리면 뜨는 게 낫겠다"고 해서 **올리면 뜨는 방식**으로 바꿨다. 박스에 마우스를 올리면 지도 페이지의 "올리면 뜨는 팝업"(`Popup`의 `tooltip` 모드)처럼 커서 근처에 놓여 커서를 따라 움직이고 박스를 벗어나면 닫힌다(마우스 이벤트는 받지 않는다). 내용은 지도 페이지 업종 팝업과 같은 행이다: 업종명(업종 배지), 시총 가중, 동일 가중, 등락 종목(▲▼■), 그룹 시총. 홈에는 업종 제외 기능이 없어 제외 버튼은 없다. 이전의 짧은 툴팁(이름 등락률)은 이 팝업에 포함돼 없앴다. 마우스를 올리면 지도 페이지의 종목 박스처럼 흰 막(35%)이 씌워지고 밝은 안쪽 테두리(2px)가 생긴다(`.overview-map-box`, 크기가 흔들리지 않게 border가 아니라 box-shadow로 그린다). 팝업 값은 홈 화면이 `OverviewMapItem`에 실어 준다(`simpleAvg`, `advancers`, `decliners`, `unchanged`). "지도 비중"(지도 안 시가총액 비율)은 요청 없이 넣었다가 사용자 지적으로 뺐다.
## 등락률 색상 입력칸에 입력 규칙 안내와 오류 이유를 보여 준다 (2026-10-15)

설정창 4-2 "등락률 색상"의 4-2-1 "(1) 등락률" 입력칸(`TreemapColorThresholdEditorPanel`의 `ThresholdRow`)은 **정수만** 받는다(-30~30, 0은 0% 칸에서만). 소수·범위 밖·0·빈 값을 넣고 칸을 벗어나거나 Enter를 누르면 알림 없이 원래 값으로 되돌아가서 "왜 안 바뀌지" 하고 헷갈렸다. 그래서 입력칸 아래에 규칙을 항상 보여 주고("정수만 입력 (-30~30, 0 제외)", 0% 칸은 "0% 구간은 색만 바꿀 수 있습니다."), 잘못 입력해 되돌릴 때는 입력칸 테두리를 붉게 하고 이유를 붉은 글씨로 4초 보여 준다. 이유 문구는 `정수만 입력할 수 있습니다.`, `-30~30 사이로 입력해 주세요.`, `0%는 0% 칸에서만 쓸 수 있습니다.`, `값을 입력해 주세요.`이다. 새로 입력하기 시작하면 오류 표시는 바로 사라진다. 알림창(팝업)은 입력할 때마다 뜨면 거슬려서 쓰지 않았다.

## 등락률 색상: 입력칸을 막대로 바꾸고 범례를 9칸으로 (2026-10-15)

4-2-1 "(1) 등락률" 입력칸은 값을 직접 쳐서 정했는데, 첫 번째 칸보다 작은 값을 두 번째 칸에 넣으면 값이 정렬되며 칸이 밀리고(두 번째 숫자가 사라진 것처럼 보임), 같은 값을 넣으면 적용할 때 색이 하나 지워졌다. 입력 규칙 안내(위 항목)로 이유를 보여 주는 것으로는 부족해서 **막대(손잡이를 끄는 방식)**로 바꿨다. 시안은 드라이브 `marketry/설정창-등락률막대-시안1장(2255)`의 1-2(가운데를 넓힌 반쪽 막대)를 골랐다.
- **막대**(`ThresholdBar`, `utils/thresholdBar.ts`): 0~30%를 **제곱근 눈금**으로 그린다(0~10%가 막대의 약 60%라 손잡이가 덜 붙는다). 손잡이는 상승 구간의 경계이고, 이웃 손잡이를 넘거나 겹치지 못하며(끌다가 닿으면 멈춤, 첫 손잡이는 1% 이상, 마지막은 30% 이하) 정수로 움직인다. 선택한 손잡이를 끌거나 ←→(1)·PageUp/Down(5)·Home/End로 옮기고, 선택하지 않은 손잡이를 누르면 그 구간을 고른다(범례 칸을 누르는 것과 같아 적용하지 않은 수정은 되돌린다). 값은 선택한 손잡이 위에 표시하고 나머지 값은 범례에 있다.
- **대칭**: 하락 구간은 상승 구간 값의 거울로만 정한다. 상승 손잡이를 옮기면 같은 순서의 하락 구간도 같은 값으로 함께 바뀐다(`handleChangeColorEditRankPercent`). 하락 칸을 눌러도 막대는 같은 순서의 상승 손잡이를 고른다. 0% 칸은 고정이라 막대가 흐려지고 색만 바꿀 수 있다. 하락 구간이 아직 없으면 기본 하락 색으로 만든다.
- **9칸 범례**: 기본 구간을 하락 4 + 0% + 상승 4의 9칸(±1/3/5/8%)으로 늘렸다(`DEFAULT_PLUS_THRESHOLDS`/`MINUS`, 명도 16·33·46·58). 지도 하단 범례 바(`ChangeRateBar`)는 칸 수에 맞춰 열 수를 정하고 9칸일 때 글자를 11px로 둔다. 설정창 맨 위 9칸 색상바는 처음에 유지했다가 **9칸이 설정창 폭에 안 들어가 지웠다**(칸 선택은 막대로 한다).
- **저장 버그**: 적용하면 **바꾼 칸만** 서버에 저장돼서 새로고침 뒤 나머지 기본 칸이 범례에서 사라졌다(예: -6% 0% +6%). 처음 적용할 때 아직 저장된 적 없는 기본 칸도 함께 저장하도록 고쳤다(`needsSave`). 취소하면 다시 열 때 고르는 칸도 처음 값으로 되돌린다.
- 이미 서버에 칸이 일부만 저장돼 있으면(한 부호에 4칸 미만) 그 칸 수 그대로 보이고 손잡이도 그 수만큼이다. 설정창의 "초기화"를 누르면 기본 9칸으로 돌아간다.
- **칸 선택(색상바를 지운 뒤)**: 막대의 손잡이(상승 쪽 구간), 왼쪽 끝의 **0% 고정 표식**(움직이지 않고 누르면 0% 칸의 색을 고른다), 막대 위 오른쪽의 **상승|하락 선택**(어느 쪽 구간의 색을 고칠지)으로 정한다. 하락을 고르면 막대 색이 하락 구간 색으로 바뀌고 값은 같다.
- **안내 문구**: 막대 아래 설명이 두 줄로 넘어가면 아래 항목이 밀려서 "하락률은 대칭값으로 자동 적용" 한 줄로 줄였다(0% 칸은 "0%는 고정, 색만 바꿀 수 있습니다.").
- **모양 통일**: 막대 손잡이와 0% 표식은 다른 슬라이더·스위치 손잡이와 같은 모양(16px 어두운 원 `zinc-800` + 얇은 밝은 테두리 `zinc-200`)이고 고른 것은 청록 테두리·링으로 표시한다. 명도 슬라이더 손잡이도 같은 모양(이전: 굵은 흰 테두리)으로 맞췄다. 상승|하락 버튼은 설정창의 다른 선택 버튼과 같은 색(고른 쪽 `var(--accent)`+검은 글자, 안 고른 쪽 `#4b4b50`+밝은 글자)이고, 눈금 글자는 다른 슬라이더 아래 글자와 같다(13px 회색, 고른 값과 같은 눈금은 흰색 굵은 글씨).

- 등락률 막대 정리: 눈금 글자는 흰색 11px(고른 값만 굵게)로 줄이고, 상승/하락 버튼이 있으므로 막대 아래 "대칭값 자동 적용" 안내 문구는 지웠다.
- 등락률 색상 설정: 상승/하락 선택 버튼을 토글처럼 알약 모양(36px)으로 맞추고, "초기화" 글자 버튼은 제목 바로 오른쪽의 새로고침 아이콘으로 바꿨다(마우스를 올리면 "기본값으로 초기화").
- 등락률 색상 설정: 막대로 칸을 고르는 구조가 되면서 "명도" 슬라이더를 없앴다. 칸 색의 밝기는 구간 순서(작은 값부터 16·33·46·58, 0%는 50)로 자동 정해지고 저장된 밝기 값은 읽지 않는다. 남은 단계는 "(1) 색상" 하나라 "(1) 등락률" 제목 글자는 지우고 상승/하락 버튼만 둔다.

- 등락률 명도 상한을 낮췄다: 15%에서 76, 30%에서 80이던 것을 15%에서 68, 30%에서 70으로(운영 지도에서 큰 하락·상승 박스의 흰 글자가 옅은 배경에 묻혀서). 8%(58)와 15%(68)의 차이는 10이다.

- 기본 색을 시안 1-1로 되돌렸다(사용자 결정, 1-2는 마음에 들지 않음): 2/5/8/15%에 채도 75·명도 16·33·46·58이 하나씩이고 첫 구간도 회색이 아닌 짙은 색이다. 색 동그라미의 선택·외곽선 표시는 box-shadow ring 대신 outline으로 그린다(웨일에서 box-shadow가 늦게 그려질 가능성을 줄이려는 시도).
- 색 동그라미의 선택 표시를 외곽선(outline/ring)에서 동그라미 안의 체크(✓)로 바꿨다. 선택한 칸의 흰 외곽선만 눈에 띄게 늦게 그려진다는 제보(크롬·Orca 모두 같음, 동작 자체는 즉시 됨) 때문이며, 체크도 늦게 뜨면 원인이 외곽선이 아니라 앱 쪽이다. 어두운 회색이 배경에 묻히지 않도록 가는 테두리(border-white/30)는 늘 두되 눌러도 바뀌지 않는다.

- 날짜를 지난 날로 고르면 날짜 옆에 붙는 문구를 "종가 (23거래일 전)"에서 "23 거래일 전"으로 바꿨다(사용자 요청). "종가" 글자는 빼고, 숫자 뒤를 띄우고, 날짜와 같은 글자색으로 한 덩어리로 보여 준다. 거래일 수를 아직 못 받았을 때만 "종가"가 보인다.
- "이미 삭제되었거나 존재하지 않는 색상 기준값입니다." 오류 창을 고쳤다: 다른 화면·탭에서 색을 지우거나 초기화해 이 화면이 들고 있는 기준값 id가 낡으면, 초기화(지우기)와 적용(수정)이 막히고 오류 창이 떴다. 지우기는 서버에 이미 없으면(404) 성공으로 보고(없애는 목적이 이미 이뤄짐), 수정은 이미 없으면 같은 값으로 새로 만든다(useTreemapCustom).
- 포인트 색(핫핑크/청록)의 구간을 25~30%에서 20~25%로 앞당겼다(사용자 결정: 25% 이상은 하루 5~20종목(평균 약 9)이라 표가 안 났고, 20% 이상은 평균 약 14종목). 20%까지는 최고 단계 색 그대로이고 20%부터 서서히 바뀌어 25%에서 완전히 포인트 색이 된다.

## 설정창 실행 취소·버튼 규격·마우스 올림 정리 (2026-10-16)

**실행 취소 용어와 한도.** 설정창 "변경 내역"의 이름을 "되돌리기·다시 적용"에서 **"실행 취소·다시 실행"**(띄어쓰기 포함)으로 정했다. 버튼, 헤더 아래 설명, 목록 줄 마우스 올림("N단계 실행 취소"/"N단계 다시 실행"), 내역이 없을 때 문구를 모두 맞췄다. 단계 한도는 종목·업종 페이지 모두 **9단계**다(종목 50→9, 업종 50→9). "실행 취소 (10)"이 버튼 칸에 안 들어가 글자가 잘렸고, 업종 페이지는 따로 50단계였던 것을 처음엔 놓쳤다. 업종·종목 변경은 바꾸는 즉시 서버에 저장돼서 되돌릴 때도 종목 수만큼 저장 요청이 나간다. "브라우저에 담아 두었다가 저장 버튼으로 반영"하는 방식은 방향은 좋지만 일괄 변경 API가 있는지 먼저 확인해야 해서 보류했다.

**실행 취소 목록 모양(종목 페이지).** 한 줄에서 두 줄로 바꿨다: 첫째 줄 종목명, 둘째 줄 `[이전 업종] → [이후 업종]`(일괄 변경은 `N개 종목` / `→ [업종]`). 업종 이름에만 대괄호를 붙인다(업종 제외·복원 확인창이 이미 `[업종명]`을 쓰는 규칙과 맞춘다). 끝의 "변경"과 종목명 뒤 콜론은 뺐다. 번호 칸은 한 자리 숫자 기준 16px, 번호와 내용 간격 12px, 줄 위아래 6px이다. 마우스를 올리면 올린 줄까지 강조색 30%로 채운다. 업종 페이지 목록은 "이동·이름 변경·순서 변경" 꼬리말이 작업 종류를 구분해서 한 줄 그대로 둔다.

**버튼 규격.** 일반 설정창 버튼은 높이 **28px, 글자 13px/500**이다(한 줄짜리가 30·34px로 뚱뚱했던 것을 하락/보합/상승 칩 높이 쪽으로 줄였다). 하락/보합/상승 칩은 12px 굵게(높이만 28), 관리자 버튼도 높이 28·13px/500이다. 글자가 두 줄인 버튼(표시 지표·박스 내 표기)은 40px 그대로다. **Basis(MARKETRY/거래소/내 분류)는 홈페이지의 메인 컨셉을 알리려는 고정 요소라 규격에서 제외**한다(높이 34, 14px, 청록). 규격 정리 때 이를 놓쳐 줄였다가 되돌렸다.

**커스텀 설정창.** 각 항목 높이를 127px로 고정해 구분선 위치를 지도·그룹과 같게 했다(135/262/389). 버튼 묶음은 지도·그룹과 같은 x=36~246(폭 210), 간격 6px이고 업종 이름 입력칸과 재배치 박스도 같은 폭이다. 색은 "강조색 채움=고른 것"이라는 설정창 규칙과 헷갈리지 않게 실행 버튼(다운로드·업로드·실행 취소·다시 실행·일괄 변경)을 어두운 회색 칩(`#4b4b50`)+흰 글자로 하고, 실행 불가는 같은 칩을 40%로 흐리게 한다. 입력칸·박스도 테두리 없는 `#4b4b50` 칩이다. 관리자 버튼만 빨강을 유지한다.

**마우스 올림.** 회색 칩(안 고른 선택 버튼, 실행 버튼)과 목록 줄(제외 업종 등)은 **강조색을 30%만 얹어 은은하게 밝힌다**(`index.css`의 `settings-chip-hover`, 비활성에는 적용 안 함). 관리자 버튼은 검정 바탕에 빨강 30%, 하락/보합/상승 칩은 선명도 변화 그대로, 고른 칸은 효과 없음이다. 간편 업종 분류 설명은 "다운받아서 AI로 간편 분류 추천"이다.

**지도 종목 박스.** 이름이 `지주우`·`홀딩스우`로 끝나면 접미어 앞에서 나눈다(한국금융/지주우, 전에는 한국/금융지주우). 포인트 색(20~25%)은 만족스러워 일주일(약 10/23까지) 써 보기로 했고, 범례 3단계 결정과 전체 지도 시안 재촬영은 그 뒤로 미뤘다.

**작업 도구.** 시안·스크린샷 파일명은 `YYYYMMDD_HHMM_이름` 순으로 앞에 날짜_시간을 붙이고, 정리(보관)할 때 그 부분을 지운다(예전 뒤쪽 `(0224)` 표기도 지웠다). 바탕화면 marketry-tools의 시안 정리는 이 규칙으로 이름을 바꿔 옮기고 개수 제한 없이 전부 옮긴다. 확인 질문은 `네/아니오`도 받고(한글 입력기는 Enter를 두 번 눌러야 한다), 질문 알림은 첫 알림 뒤 120초 간격으로 5번까지다.

## 지도 업종 헤더를 종목 박스와 구별한다 (2026-10-16)

지도에서 업종 박스와 종목 박스가 시각적으로 구별되었으면 해서 여러 안을 시안으로 비교했다(드라이브 `지도업종명-구별-시안`, `지도업종헤더-화살표-시안`). **특수기호 마커(■ ▸ ◆)는 등락 종목 수 표시(▲▼■)와 헷갈려서 뺐다.** 대괄호는 알림창의 업종 표기와 같아 무난하지만 아쉬워서 다른 마땅한 안이 없을 때 쓰기로 했다.

처음 적용한 "이름 칩 + 진한 푸른 헤더"(모든 단계 `#1e2a3a` + 아래 선, 앞의 점 제거)는 **단계별 밝기와 점이 사라지는 것을 알리지 않고 넣어서** 사용자가 되돌렸다. 최종: 헤더 바탕은 원래 단계별 색(최상위 검정, 1단계 `#333`, 2단계 `#4d4d4d`)을 그대로 두고, **앞의 표시·업종 이름·등락률 값을 함께 옅은 배경 배지에 담는다(칩 범위 시안 2번)**(`SectorBox.tsx`). 앞의 표시는 1단계 점(`·`) 대신 작은 삼각 화살표 `▸`(화살표 시안 2번), 2단계는 화살표 두 개 `▸▸`다. 배지 색은 흰색을 단계별로 진하게 쓴다(대분류 18%, 중분류 24%, 소분류 30%. 강조 색상은 강세 업종 헤더를 가리키는 색이라 배지에 쓰지 않는다. 헤더 바탕 단계 차이가 작아 같은 투명도로는 중분류·소분류가 비슷해 보였다). 강세 업종(채워진 라임 헤더)은 그대로다. 왼쪽 세로 막대는 후보로 남긴다.

이어서 정한 것: 헤더 자체의 왼쪽 들여쓰기(4px)를 빼서 배지가 박스 왼쪽 끝에 붙고(강세 업종 채운 헤더는 글자가 붙지 않게 유지), 홈 틀 제목(시장 지도 등)의 왼쪽 4px도 뺐다. 등락률 등 헤더 오른쪽 글자는 이름의 0.9배로 작게 하고, 소분류 `▸▸`는 화살표 사이를 글자 간격 -0.15em으로 좁혔다. 화살표는 상세 보기에서도 전체 트리 기준 깊이(중분류 `▸`, 소분류 `▸▸`)를 그대로 쓴다. 지도 이동 경로(`ALL STOCK ⤺ 업종`)의 왼쪽 들여쓰기는 빼 봤다가 별로라서 되돌렸다.

## 설정창 번호와 관리자 페이지 (2026-10-16)

탭이 없는 설정창(그룹·커스텀)에도 지도 설정창처럼 항목 이름 앞에 `1)`, `2)`, `3)` 번호를 붙였다(`index.css`의 `.settings-plain-content` 번호 규칙, 번호 칸 19px, 화면에 보이는 순서대로 자동). 항목이 하나뿐인 홈 설정창도 `1)`을 붙인다(처음엔 점으로 뒀다가 사용자가 번호를 원해 바꿨다). 탭 메뉴를 만들기엔 항목이 적어서 번호만 쓰기로 했다.

커스텀 설정창의 **관리자 항목(ADMIN, UPDATE, ROLLBACK)이 관리자 계정에만 보여서 번호가 사용자마다 달라지는 문제**가 있어, **관리자 페이지(`/admin`)를 만들어 옮겼다**(`AdminPage.tsx`). 상단 메뉴에 `Admin`이 관리자 계정에만 보이고(`NavSubBar`), 관리자가 아니면 "관리자만 볼 수 있는 페이지입니다." 안내만 보인다(자동으로 홈으로 보내면 로그인이 끝나기 전에 잘못 쫓겨날 수 있어 이동하지 않는다). 서버는 `/api/admin/**`을 ADMIN만 허용한다(`AuthConfiguration`). 이제 커스텀 설정창 번호는 누구에게나 같다(종목: 간편 업종 분류 1, 변경 내역 2, 일괄 변경 3 / 업종: 업종 추가 1, 업종 재배치 2, 변경 내역 3). 관리자 항목이 빠지면서 각 항목의 구분선은 지도·그룹과 같은 135/262/389px 그대로 맞는다.

관리자 페이지는 다른 페이지처럼 **가운데 메인 영역 + 옆 설정창** 구조다. 작업(ADMIN·UPDATE·ROLLBACK)은 설정창 `1) MARKETRY 맵`에 있고, 메인 영역에는 다른 페이지가 불러오는 동안 보여 주는 홈페이지 로고 원(`Spinner still`)만 둔다. 로딩 원과 같은 모양이지만 돌지도 경과 시간 숫자를 세지도 않는다.

로컬 개발 전용 **"개발 · 테스트 회원으로 전환" 버튼을 계정 메뉴에서 Admin 설정창(`2) 테스트 회원 (로컬 전용)`)으로 옮겼다**(운영 화면에는 원래부터 나오지 않는다). 전환 규칙은 `useTestMemberToggle` 한 곳에 모았다. 다만 테스트 회원은 일반(USER) 계정이라 **Admin 페이지에 들어올 수 없어서**, 테스트 회원일 때 원래 계정으로 돌아오는 버튼은 계정 메뉴에 남겼다(테스트 회원일 때만 보인다). 설정창 버튼은 "맵 서버 업로드" 항목처럼 번호가 붙은 항목이다.

계정 메뉴도 정리했다(`NavBar.tsx`): 프로필·로그아웃 버튼을 버튼 규격(높이 28px, 13px/500, 모서리 5px, 간격 6px)에 맞추고, 메뉴가 프로필 사진 **아래가 아니라 왼쪽에** 뜬다(아래로 열리면 오른쪽 위 설정창 영역을 덮었다). 프로필 사진에는 청록색 0.5px 외곽선을 둔다(1px와 2px도 비교했고 0.5px가 낫다고 했다. 1배 화면에서는 1px처럼 보일 수 있다).

Admin 설정창을 다듬었다: 빨간 `ADMIN` 줄을 없애고 경고 표시는 설정창 헤더 오른쪽 끝으로 옮겼다(`SettingsPanel`의 `headerRight`). 처음에는 빨간 `⚠ ADMIN` 배지였다가 **빨간 경고 아이콘만** 남겼고, 지도 설정창 헤더의 되돌리기·저장 아이콘과 같은 칸(24px)·아이콘(20px) 크기와 자리를 쓴다. `1) 맵 서버 업로드` 아래에 설명 "- MARKETRY 맵 업데이트"를 넣고, 버튼 글자를 UPDATE·ROLLBACK에서 **업데이트·롤백**으로 바꿔 앞에 아이콘을 하나씩 붙였다(업데이트는 구름 위 화살표 — 커스텀의 업로드 아이콘과 모양이 겹치지 않게, 롤백은 기록 시계. 처음의 새로고침 모양은 "새로고침 같다"고 해서 바꿨다). 항목 이름 "2) 테스트 회원"에는 "(로컬 전용)"을 붙였다.

Admin 설정창의 버튼 이름을 **업데이트에서 커밋으로 바꿨다**(롤백과 짝이 맞는 말이고, 올릴 때마다 버전이 하나씩 남고 롤백이 그 버전을 고르는 구조라 "버전을 확정한다"는 뜻에 가깝다. 업데이트가 한글이고 롤백이 영어라는 말의 종류 차이도 줄었다). 아이콘은 git 커밋 모양(`CommitIcon`)이다. 확인창 제목(`MARKETRY 커밋`)·안내 문구·완료/실패 알림("커밋 완료", "커밋 실패")과 설명 "- MARKETRY 맵 커밋"도 같은 말로 맞췄다. 개발 작업의 "커밋"과 말이 같아 헷갈릴 수 있지만 이 페이지는 관리자만 본다. 앞서 보던 구름 아이콘은 "동기화 같다"는 말이 있어 커밋 모양으로 바꿨다.

커밋 버튼 아이콘은 시안에서 **세로 커밋(원 + 세로선, 3번)**으로 정했다(작은 원 + 가로선은 16px에서 가늘어 잘 안 읽혔다). 헤더는 동작이 아니라 대상인 **"MARKETRY 분류"**, 설명은 **"- 내 분류를 MARKETRY 분류로 커밋·롤백"**, 확인창은 "내 분류를 MARKETRY 분류로 커밋하시겠습니까?"·"MARKETRY 분류를 되돌리시겠습니까?"로 정했다(바뀌는 것은 지도가 아니라 **지도가 따르는 분류**다. Basis의 MARKETRY·거래소·내 분류가 분류 방식이고, 관리자가 편집한 내 분류가 MARKETRY 분류가 되면 그 결과로 사용자 지도가 달라진다. 결과를 알리는 둘째 줄 "유저들이 보는 MARKETRY 맵이 변경됩니다."는 그대로 둔다)(이 동작은 관리자가 편집하는 **내 분류가 MARKETRY 맵이 되는 것**이라 "무엇을 → 무엇으로"가 보이게 했다. "MARKETRY 맵을 서버에 커밋"은 대상이 거꾸로라 어색했고, "관리자 분류"·"운영자 분류"는 화면의 다른 곳에 없는 이름이라 뺐다). 헤더·버튼·확인창·알림이 모두 같은 말(커밋·롤백)이라 어긋나지 않고, "동기화"처럼 방향이나 자동성을 오해할 말이 없다. 사이에 "맵 동기화"로 바꾼 것은 아이콘 선택을 문구 선택으로 잘못 읽은 것이라 되돌렸다.

관리자 페이지의 빨간 경고 아이콘(`WarningIcon`)을 설정창 헤더 오른쪽에 이어 **메인 영역의 정지된 로고 원 안, 로딩 때 경과 시간 숫자가 있던 자리(로고 아래)에도** 놓았다(`Spinner`의 `stillContent`).

관리자 전용 표시 아이콘은 경고 삼각형(느낌표가 작아 보였다)에서 **자물쇠(`LockIcon`)**로 바꿨다(시안 8번, 빨강). 설정창 헤더 오른쪽과 메인 영역 로고 원 안(경과 시간 숫자 자리) 두 곳 모두 같은 아이콘이다. 선 굵기는 헤더의 다른 아이콘과 같은 1.6이다.
