# 프론트 작업 진행 프로세스

로컬 검증 실패는 오류 보고만으로 종료하지 않는다. 공통 원본의 실패 처리 절차에 따라 원인을 진단하고 승인된 범위의 문제를 수정한 뒤 검증을 다시 통과시켜 커밋·PR 작업을 이어간다. 사용자의 결정·관리자 작업이 실제로 필요한 경우에만 구체적인 조치를 요청한다.

공통 검증·커밋·PR·CI 확인·배포 절차는 `/Users/chanju/Projects/marketry/AGENTS.md`에서 관리한다. 먼저 공통 원본과 이 저장소 `AGENTS.md`를 읽는다.

- 실제 변경 전에는 적용할 기준과 변경 방향을 설명하고 결정된 방향으로 진행한다.
- 코드 변경 후와 커밋·PR 전에는 `npm run lint`, `npm test`, `npm run build`를 모두 통과한다. 검사 실행 차단도 미검증이며, 통과하지 않은 변경을 PR로 넘기지 않는다.
- PR은 기능·되돌릴 단위별로 나눈다. 큰 작업은 단계별로 진행하되 서로 무관한 하루 작업 전체를 하나의 PR로 묶지 않는다.
- 커밋·푸시 전 열린 PR과 현재 브랜치의 병합 이력을 확인하는 방법은 공통 원본을 따른다.
- 배포 요청은 프론트 자산 발행과 후속 nginx 배포 성공 확인까지 포함한다. PR CI가 없는 현재 구성에서 `gh pr checks`나 존재하지 않는 검사를 기다리지 않는다.
- UI·설정·색상 기준은 `docs/ui-areas.md`, `docs/ui-colors.md`를 따른다. 커밋 형식은 `docs/rules/commit.md`를 따른다.
